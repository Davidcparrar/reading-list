## 1. Agentic Behavior Engineering: A Design-by-Contract Methodology for Specifying, Verifying, and Governing Enterprise AI Agents
- **Authors:** Yang Song
- **arXiv:** https://arxiv.org/abs/2611.05454
- **Theme:** T3 (also T2)
- **Summary (mine):** Treats observable agent behavior — not prompts or model weights — as the versioned artifact under change control, and adapts Design-by-Contract to non-deterministic LLM systems by expressing per-scenario rules as stable, ID'd behavior contracts. Release gating is driven by a pass^k reliability metric computed over a scenario suite that includes capacity/allocation boundaries, so a release is allowed only when the contract is met at a chosen reliability level.
- **Relevance:** Direct answer to "how do we specify and verify what an agent must do?" using a familiar formal methods vocabulary (DbC), with an explicit evaluation protocol and governance surface.

## 2. AgentTrustCI: Build-Time Policy, Grounding, and Trajectory Tests for Java LLM Agents
- **Authors:** Sachin Gupta
- **arXiv:** https://arxiv.org/abs/2611.06674
- **Theme:** T3 (also T1 — agentic evaluation)
- **Summary (mine):** Proposes a JUnit 5 framework that turns informal expectations about a Java LLM agent into three kinds of build-time checks: policy, grounding, and trajectory, each run against recorded agent traces. The paper evaluates the framework on 55 synthetic cases and is careful to note that the reported numbers describe regression-suite coverage rather than production correctness.
- **Relevance:** A spec-driven view of agent CI: declared contracts become unit tests over traces, which fits the "formal methods for coding agents" theme at the toolchain layer.

## 3. EvoCodeAgent: Project-Level Code Generation via Architecture-Code Co-Evolution and Experience-Guided Repair
- **Authors:** Qianhui Zhao, Li Zhang, Fang Liu
- **arXiv:** https://arxiv.org/abs/2611.06328
- **Theme:** T3 (also T1)
- **Summary (mine):** Generates multi-file projects from structured specifications by maintaining an evolving architectural state that is reconciled against discovered code relations, and repairs failures using evidence gathered from tool-based verification. The authors report a 60.48% unit-test pass rate on DevBench under a GPT-5 backbone.
- **Relevance:** Spec-driven code generation with a verification feedback loop at project scale — the exact seam where "spec → code → check" lives for coding agents.

## 4. ATC: Agent Trajectory Control for Role-Contract Enforcement in Black-Box Multi-Agent Systems
- **Authors:** Maisha Maliha, Vishal Pramanik, Sumit Kumar Jha
- **arXiv:** https://arxiv.org/abs/2611.04321
- **Theme:** T2 (also T3)
- **Summary (mine):** Enforces each agent's role as a contract applied at the message boundary: a controller inspects outgoing messages against the role spec, detects drift, and regenerates non-compliant turns before they enter the shared conversation. The approach is black-box, so it works over hosted LLMs without model access.
- **Relevance:** Bridges multi-agent orchestration and specification: role contracts become a runtime enforcement layer, which is a concrete protocol-level mechanism for team architectures.

## 5. Airlock: Bounding the Multi-Agent Blast Radius via Selective Online Containment
- **Authors:** Zhonghao Zhan, Javad Forough, Yefan Zhang, et al.
- **arXiv:** https://arxiv.org/abs/2611.06727
- **Theme:** T2
- **Summary (mine):** A runtime for multi-agent workflows that traces a provenance graph over inter-agent messages and selectively freezes only the branches tainted by a faulty output, instead of halting the whole workflow. Guardrails are evaluated as contained interventions rather than global kill-switches.
- **Relevance:** Treats orchestration as fault-isolation plus provenance — a different design axis for multi-agent architectures than role/tool assignment, and directly on-theme for multi-agent coordination.

## 6. Route Anything: A Study of Model and Policy Routing for General-Purpose AI Systems
- **Authors:** Pengfei Zhou, Yixing Ma, Hexin Wang, et al.
- **arXiv:** https://arxiv.org/abs/2611.05275
- **Theme:** T2 (also T1)
- **Summary (mine):** An empirical study of routing: when to send a query to which model and under which policy, framed as a general-purpose orchestration decision rather than per-task heuristics. The paper tries to map how routing policies interact with model heterogeneity and workload shape.
- **Relevance:** Core orchestration primitive for any multi-agent or model-pool system; useful priors for designing coordinators.

## 7. ToolSpace: Scaling Tool-Centric Environment Synthesis for Long-Horizon Agents
- **Authors:** Guanting Dong, Zhichao Sun, Xinyu Yang, et al.
- **arXiv:** https://arxiv.org/abs/2611.05036
- **Theme:** T2 (also T1)
- **Summary (mine):** Trains long-horizon tool-using agents by synthesizing training environments from execution-verified tool sequences, so the supervision signal comes from traces that actually ran rather than from static tool documentation. Scaling the synthesized environment coverage improves downstream tool coordination.
- **Relevance:** A practical recipe for the data side of multi-agent/tool-using systems; complements routing and role-control work.

## 8. What Does Multi-Turn Reinforcement Learning Really Improve in LLM Agents?
- **Authors:** Kejian Zhu, Zhuoran Jin, Shangqing Tu
- **arXiv:** https://arxiv.org/abs/2611.06483
- **Theme:** T1
- **Summary (mine):** Isolates where multi-turn RL actually helps agents by breaking gains down against turn budget, and shows that advertised improvements collapse at the wrong budget. Introduces a BudgetMix RL recipe that trains across turn budgets so the policy is not overfit to a single horizon.
- **Relevance:** Sober, causal look at "what did agentic RL buy us?" — directly useful for anyone fine-tuning agents and claiming reasoning gains.

## 9. Routes of Reasoning: Steering LLM Reasoning via MoE Router Signals
- **Authors:** Shengjie Wang, Mohsen Fayyaz, Nanyun Peng
- **arXiv:** https://arxiv.org/abs/2611.05919
- **Theme:** T1
- **Summary (mine):** Reads mixture-of-experts router activations as a window into reasoning behaviors, then steers them at inference time to cut unnecessary chain-of-thought. The reported median token reduction is around 30% with little accuracy loss.
- **Relevance:** Mechanistic handle on reasoning efficiency inside MoE models, a direction with real deployment cost implications.

## 10. Think Less, Locally: Local Preference Learning for Reasoning Compression
- **Authors:** Muyao Yuan, Liyan Xu, Weizhan Zhang
- **arXiv:** https://arxiv.org/abs/2611.04814
- **Theme:** T1
- **Summary (mine):** Applies local DPO over frozen reasoning prefixes so the model learns to shorten reasoning without derailing early correct work, targeting the "overthinking" failure mode. Reported math completion length drops by about 42–45% at comparable accuracy.
- **Relevance:** PEFT-flavored fine-tuning aimed squarely at reasoning compression; a counterpart to the MoE-router approach in paper 9.
