## 1. Your Policy Is Secretly a Harness: The Decision Geometry of Agent Interfaces
- **Authors:** Jian Mu, Ruibo Shen, Yao Shu
- **Summary:** The paper argues that measured agent performance conflates two separable factors: what the harness exposes to the policy (tool surface, prompt shape, action vocabulary) and how skillfully the policy navigates that surface. It formalises these as a "decision geometry" and shows that fair harness comparisons require disentangling them, otherwise a stronger harness can be credited to the model and vice-versa. The authors use this to re-interpret published harness-vs-harness results and propose a protocol for separating the two contributions.
- **Theme:** (1) core LLM — agentic-system evaluation.
- **Relevance:** Directly addresses a measurement bias that recurs in every agent benchmark the user tracks; practical for anyone comparing harnesses.
- **Link:** https://arxiv.org/abs/2610.37255

## 2. The Trinity: Capability-Driven Recursive Self-Improvement for Multimodal Agents
- **Authors:** Weidong Tang, Ruiheng Wang, Jingxuan Zhang, et al.
- **Summary:** Trinity splits a self-improving multimodal agent into three cooperating roles — Creator (proposes tasks), Explorer (attempts them), Evolver (rewrites the shared toolbox) — and reorganises training examples by the underlying capability they exercise rather than by surface task form. Simulated worlds generate reusable harness modules that a capability-aware router then dispatches to. The result is a role-decomposed orchestration pattern aimed at compounding improvement across modalities.
- **Theme:** (2) multi-agent frameworks & orchestration.
- **Relevance:** Clean example of role-and-tool-assignment orchestration; the capability router is the interesting primitive.
- **Link:** https://arxiv.org/abs/2610.36077

## 3. Work Agents: Systems, Capabilities, and Optimization
- **Authors:** Zishan Xu, Enjun Du, Mingqi Gao, et al.
- **Summary:** A systematisation paper that frames "work agents" as foundation-model-plus-harness systems doing stateful digital work, and introduces two dimensions (persistence, openness), five canonical work forms, and five capability families. It then surveys optimisation and evaluation methods against those axes, giving a vocabulary for comparing today's agent architectures.
- **Theme:** (2) multi-agent frameworks & orchestration (architectural taxonomy).
- **Relevance:** Useful reference frame for talking about agent architectures beyond specific implementations.
- **Link:** https://arxiv.org/abs/2610.35845

## 4. Harness-Model Collaboration for Long-Horizon Continual Learning (HaMo)
- **Authors:** Zhen Bi, Zhizhi Peng, Yan Wang, et al.
- **Summary:** HaMo pairs a fast retrieval layer over "strategy-level experience cards" with slow parametric updates to the underlying model, so that web agents accumulate transferable multi-step workflows without forgetting prior ones. The split lets the harness carry what changes often (workflow fragments) while the model absorbs what stabilises (reusable primitives). Reported gains come from long-horizon domain-transfer tasks.
- **Theme:** (2) multi-agent frameworks & orchestration.
- **Relevance:** Concrete design for separating fast harness memory from slow model memory — a recurring question for persistent agents.
- **Link:** https://arxiv.org/abs/2610.34724

## 5. Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions
- **Authors:** Anouar Imel, Imad Charradi, Abderrahman Sghir, Khalil El Khammar
- **Summary:** The paper studies the common pattern of summarising a multi-agent discussion into a short memory and handing it to a decision-maker LLM, using a CrossProfile benchmark. It shows that both rarity and relevance heuristics for selecting which agent utterances to keep end up biasing the final decision, and that speaker-attribution tags themselves distort which claims the decider trusts. The result is a diagnostic for how group-to-summary compression quietly corrupts multi-agent outcomes.
- **Theme:** (2) multi-agent frameworks & orchestration (communication / summarisation protocols).
- **Relevance:** Hits the "how do agents communicate to a decider" question with concrete failure modes.
- **Link:** https://arxiv.org/abs/2610.37624

## 6. Omni-InteractScope: Benchmarking Proactive and Agentic Interaction in Continuous Omnimodal Streams
- **Authors:** Yinsong Yan, Ling Wang, Yuxuan Wang, et al.
- **Summary:** Introduces a 1,479-interaction benchmark that scores omnimodal models on three agentic behaviours a static QA benchmark cannot: calling a tool at the right moment, raising an unprompted reminder, and sustaining guidance across a stream. Current frontier models perform poorly on all three, giving a quantitative handle on "proactivity" rather than reactive accuracy.
- **Theme:** (1) core LLM — agentic-system evaluation.
- **Relevance:** Tests temporal/initiative behaviour that most agent evals skip.
- **Link:** https://arxiv.org/abs/2610.35439

## 7. SearchHorizonBench: A Benchmark for Search Value in AI Agents
- **Authors:** Jingjie Ning, Xueqi Li, Yibo Kong
- **Summary:** The authors run 45,632 agent executions to measure the marginal value of each additional search action and then study how well that value can be predicted ahead of time. Historical calibration offers only a small lift, meaning agents cannot reliably decide when another search is worth the cost — a direct planning-under-uncertainty finding.
- **Theme:** (1) core LLM — planning / tool-use evaluation.
- **Relevance:** Surfaces a measurable gap in agent planning; useful for anyone building a search-tool budget heuristic.
- **Link:** https://arxiv.org/abs/2610.34714

## 8. MLE-World: Predicting Machine Learning Experiment Outcomes with a Learned World Model
- **Authors:** Brian Ko, Han Wang, Hejia Geng, Li Erran Li, Sherry Yang
- **Summary:** MLE-World fine-tunes a model to predict the result of running an ML program without executing it, then plugs that predictor into AI-research agents so that only low-confidence candidates are actually executed. The resulting test-time-scaling policy cuts compute while preserving solution quality across their evaluation suite.
- **Theme:** (1) core LLM — planning / agentic test-time scaling.
- **Relevance:** Interesting template for cheap candidate filtering before expensive verification.
- **Link:** https://arxiv.org/abs/2610.37175

## 9. VibeVideoBench: Evaluating Multimodal Agents on Code-Driven Video Generation
- **Authors:** Xiong Wang, Tianke Zhang, Haonan Fan, et al.
- **Summary:** A 239-task bilingual (EN/ZH) benchmark where agents must write code that renders a finished MP4 with audio satisfying a given spec. Top systems meet most *content* requirements but routinely violate the *delivery* contract (timing, duration, format), isolating a correctness-of-output axis that pure code-quality metrics would miss.
- **Theme:** (1) core LLM / (3) spec-driven coding crossover — agents writing code to satisfy an executable spec.
- **Relevance:** Closest thing in-window to spec-driven coding evaluation; the "pass/fail-against-spec" framing matters for the user's theme (3).
- **Link:** https://arxiv.org/abs/2610.35864

## 10. PhysEvolve: Verifier-grounded Self-evolution for Physical Reasoning with Executable Worlds
- **Authors:** Jinyuan Hu, Yilei Jiang, Chen Tang, Minghong Cai, Xinran Liu, Xiangyu Yue
- **Summary:** A VLM proposes executable physics scenes, a physics engine *verifies* them and generates counterfactual tasks, and the verifier's judgments feed GRPO training of the VLM. The loop is a working example of "programmatic verifier in the training objective," which is the structural idea closest to spec-driven correctness for coding agents even though the domain here is physics.
- **Theme:** (3) spec-driven / formal verification — nearest in-window analogue (physics engine as verifier, not a theorem prover).
- **Relevance:** Included to represent theme (3) with the caveat above; no in-window paper this cycle directly tackled formal methods for code.
- **Link:** https://arxiv.org/abs/2610.34921
