# Reading digest — 2026-09-18

Found 10 paper(s) in the last 48h window.

## 1. Rethinking Critic Learning in PPO: Understanding and Mitigating Value Flattening
- **Authors:** Yizhuo Li, Jianhao Yan, Yun Luo, et al.
- **Summary:** The paper diagnoses a previously unnamed failure of PPO critics on LLM RL, "value flattening", where Monte-Carlo state values swing sharply between intermediate states but the critic's predictions stay smooth — a bias traced to an implicit variance penalty and to redundant updates from correlated states. The authors propose SP³O, which supervises the value loss on only a few well-separated states per response, and show on Qwen3-Base that even three sparsely-supervised states per response are enough to flatten the flattening effect and lift policy quality across model sizes and evaluation suites.
- **Theme:** Core LLM advances (fine-tuning / RL for LLMs)
- **Relevance:** Names and mitigates a concrete pathology in the most widely-deployed LLM RL algorithm; the fix is a one-line change to standard PPO pipelines.
- **Link:** https://arxiv.org/abs/2609.18708

## 2. RetireOPD: Self-Retiring On-Policy Distillation for Agentic Reinforcement Learning
- **Authors:** Yan Yu, Zhengxi Lu, Yizhou Liu, et al.
- **Summary:** RetireOPD tackles two under-recognised issues in agentic RL — privileged teachers that are still not reliable, and distillation whose usefulness varies across training stages — by first training a decoupled skill-conditioned teacher with environment rewards and then jointly running RL and on-policy distillation for a skill-free student. Its key mechanic is Adaptive Retirement: the student drops the teacher on its own once the two stop diverging and it reaches a target fraction of the teacher's success rate, avoiding the brittleness of hand-tuned distillation schedules.
- **Theme:** Core LLM advances (agentic-system fine-tuning)
- **Relevance:** A rare treatment of when to *stop* using a teacher during agent training — orthogonal and complementary to most reward-shaping work on multi-turn agents.
- **Link:** https://arxiv.org/abs/2609.20784

## 3. When EOS Tokens Disagree: Understanding Length Inflation in On-Policy Distillation
- **Authors:** Yuxiao Yang, Tianrun Yu, Shangzhe Li, et al.
- **Summary:** The authors show that on-policy distillation blows up student response length because base students and post-trained teachers place stopping probability on different EOS tokens even when they nominally share the same stop set (Qwen3, Llama, Gemma). Simply unifying the decoding stopping set is not enough; treating functionally-equivalent EOS tokens as a shared semantic stop action substantially reduces mismatch-driven inflation, and a stage-wise study reveals a second, later-training source of inflation that persists past termination alignment.
- **Theme:** Core LLM advances (fine-tuning / distillation)
- **Relevance:** Practical, reproducible diagnostic for a bug most distillation pipelines silently ship, with a cheap and cross-family fix.
- **Link:** https://arxiv.org/abs/2609.20511

## 4. A Zeroth-Order Paradigm for LLM Preference Alignment
- **Authors:** Peter Chen, Xi Chen, Wotao Yin, Tianyi Lin
- **Summary:** ComPO recasts direct preference alignment as a zeroth-order comparison-oracle problem, extracting directional signal from pairs that DPO-family methods struggle with (small likelihood margins, likelihood-displacement failures) without optimizing a differentiable preference loss on them. The authors prove convergence for the offline scheme under smoothness / gradient-sparsity / oracle-compatibility assumptions, add an online variant with reverse-KL control over unlabeled generations, and report improvements over DPO-family baselines across Mistral, Llama, Gemma-2/3 and Qwen3.
- **Theme:** Core LLM advances (fine-tuning / alignment)
- **Relevance:** A theoretically-grounded alternative to the DPO family that directly addresses likelihood displacement, one of the field's known open pathologies.
- **Link:** https://arxiv.org/abs/2609.19144

## 5. DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression
- **Authors:** DeepSeek-AI, Anyi Xu, B. Li, et al.
- **Summary:** DeepSeek-V4.1-Flash is a 552B multimodal MoE with a Causal Encoder-Decoder that spends only 8B active parameters on prefill (versus 16B on decode), pretrained on 45T tokens to serve input-heavy agentic workloads at one-million-token context. The team stacks cross-layer KV reuse (CSA2) with FP4 KV caching to cut the always-in-HBM KV cache to ~890 bytes per token (≈1/4 of V4-Flash), and adds SWA Bounded Replay to shrink the persistent SSD/host KV cache to ~1/8, while still improving downstream performance.
- **Theme:** Core LLM advances (long-horizon agent inference infrastructure)
- **Relevance:** Frontier MoE recipe explicitly designed for long-horizon *agentic* deployment; the KV-compression numbers are the sort other agent stacks will have to catch up to.
- **Link:** https://arxiv.org/abs/2609.19969

## 6. Agora: Git as Shared Memory for Collective AutoResearch
- **Authors:** Yifan Zhang, Yunheng Zou, Shaokun Zhang, et al.
- **Summary:** Agora treats a git DAG of immutable commits as the coordination substrate for many concurrent AutoResearch coding agents — every result, insight, hypothesis, verification, or report is a commit, and a derived index exposes the frontier plus a diversity-aware selection rule that stops the swarm from monoculture. In a ~12-day, 13-worker unplanned run on a weight-transfer problem across 141 donors and a 119.6M-param hybrid target, the community posted 1,703 contributions, closed 62% of the gap to a trained GPT-2 124M (3.39 → 1.899 bits/byte), and produced a 145-commit ancestry across 15 accounts with 165 independent reproductions.
- **Theme:** Multi-agent frameworks & orchestration (coordination, communication protocol)
- **Relevance:** A concrete, deployed answer to how to scale many autonomous coding agents without duplicated search — one of the most direct multi-agent orchestration contributions of the window.
- **Link:** https://arxiv.org/abs/2609.18094

## 7. SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness
- **Authors:** Haozhe Liu, Tian Ye, Sensen Gao, et al.
- **Summary:** SoL-Pi runs recursive-self-improvement style auto-research loops *at the harness layer*, spanning many environments so that the surviving mechanisms transfer beyond their development setting; four survive selection (action execution, context compaction, observation handling, delegated reading). On the 51-task EdgeBench evaluation SoL-Pi matches the Pi harness across GPT-5.6 Sol and Opus 5 while cutting token traffic by 44.7–49.0% and API cost by roughly a third, estimated as $8.75–13.50/hour of savings over native Codex/Claude Code harnesses.
- **Theme:** Multi-agent frameworks & orchestration (agent architectures for coding agents)
- **Relevance:** Rare study of harness-level improvements that transfer across models and environments — directly actionable for anyone running long-horizon coding agents.
- **Link:** https://arxiv.org/abs/2609.20519

## 8. An Empirical Study of Harness Design for Coding Agents
- **Authors:** Run-Ze Fan, Zihao Zhang, Simin Ma, et al.
- **Summary:** Fixing a lightweight harness's execution loop, the authors vary planning, action space, and context management independently across four models on SWE-Bench Verified and Terminal-Bench 2.1 (176 matched settings). Their component-level findings: context management matters most as the context budget shrinks and mostly by preventing overflow failures; staged rule-based elision before LLM summarisation is the best context strategy; planning shifts from an accuracy scaffold for weak models to a cost saver for strong ones; predefined tools help bash-weak models while bash-capable models are cheaper with a bash-only interface.
- **Theme:** Multi-agent frameworks & orchestration (agent architectures for coding agents)
- **Relevance:** The clearest ablation-based decomposition of what harness components actually contribute to coding-agent performance, useful for anyone tuning agent frameworks.
- **Link:** https://arxiv.org/abs/2609.20804

## 9. ProgramDistill: From Interactive Web Apps to Verifiable Reference-Guided SWE Tasks
- **Authors:** Jeonghye Kim, Minseon Kim, Young Jin Kim, et al.
- **Summary:** ProgramDistill benchmarks coding agents that must *infer* required behaviour from a fully functional reference application and re-implement it in an incomplete one, decomposing apps into features whose replayable behaviours are executable via a gold patch. Their mine-craft-patch pipeline auto-derives 1,975 replay-verified behaviours across 26 applications into 4,063 tasks; on nine frontier agents, GPT-6 Astra and Claude Opus 5 hit 49.2% and 28.8% on full-app cumulative workflows, while partial-app reconstruction drops from 100% → 64.0% and 96% → 32% as restoration depth grows.
- **Theme:** Spec-driven / formal verification for coding-agent correctness
- **Relevance:** A live "spec = executable reference" evaluation regime — closes the loop between behaviour specification, verification, and agent correctness without human-authored issue text.
- **Link:** https://arxiv.org/abs/2609.18805

## 10. ScienceIDE: Turning World's Scientific Codebase into Agent Learnable Environments
- **Authors:** Hejia Geng, Zesen Huang, Haoyang Li, et al.
- **Summary:** ScienceIDE converts scientific repositories into executable environments programmable by agents, using expert-defined scientific cases and acceptance criteria as the verification contract for task generation, execution, and grading. The resulting verified interaction trajectories feed an SFT/RL/eval loop that produces PhAI-IDE-72B/9B/4B, which improve held-out scientific-code repair and show positive transfer to general code, reasoning, and knowledge benchmarks — evidence that spec-anchored scientific experience trains better generalist coders.
- **Theme:** Spec-driven / formal verification for coding-agent correctness
- **Relevance:** Rare, concrete instantiation of acceptance-criteria–driven verification as the reward substrate for training coding agents on real repositories.
- **Link:** https://arxiv.org/abs/2609.19134
