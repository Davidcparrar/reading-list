## 1. OneDayAgent: Towards a Long-Horizon Harness for Autonomous Agents

- **Authors:** Jingsheng Zheng, Xinyuan Fang, Jintian Zhang, et al.
- **Summary:** Proposes a harness that turns a single LLM into a durable long-horizon agent by decomposing an incoming task into bounded subtasks, carrying an execution memory forward under context pressure, and running a verify-and-repair loop over the final deliverable before returning it. The interesting move is treating "context management" and "self-verification" as first-class harness stages instead of leaving them to the base model. Reports gains on long-running deliverable tasks where flat ReAct-style loops typically collapse from context bloat.
- **Theme:** (2) Multi-agent frameworks & orchestration
- **Relevance:** Directly targets the orchestration layer above the LLM — the "harness" abstraction is exactly the kind of pattern this list is tracking.
- **Link:** https://arxiv.org/abs/2608.05013

## 2. TurnSight: Turn-Level Hindsight Self-Distillation for Tool-Integrated Reasoning

- **Authors:** Changle Qu, Sunhao Dai, Hengyi Cai, et al.
- **Summary:** For agents that interleave reasoning steps with tool calls, credit is normally assigned only at the trajectory level, so a good-plan/bad-tool-call turn gets the same signal as a bad-plan turn. TurnSight generates several hindsight rewrites of each turn conditioned on the *actual* tool-execution outcome, then keeps the ones that agree across horizons as training targets for self-distillation. The result is finer-grained per-turn supervision without needing a separate reward model.
- **Theme:** (1) Core LLM advances — fine-tuning for tool-using reasoning
- **Relevance:** Concrete PEFT-style recipe for the exact failure mode (per-turn credit assignment) that shows up when moving from single-shot LLM calls to tool-using agents.
- **Link:** https://arxiv.org/abs/2608.04007

## 3. FocusMem: Factorizing Content, Readout, and Trust in Latent GUI Memory

- **Authors:** Zhuoran Zhang, Bowen Li, Jingcheng Ju, et al.
- **Summary:** For GUI agents that accumulate screen observations, FocusMem separates three memory concerns that are usually tangled: what is stored (a latent representation of past screens), how it is retrieved (a state-conditioned readout that produces a decision-specific view rather than a static summary), and how much it is trusted at decision time. The framing is a step toward memory that behaves like working memory instead of a growing scratchpad.
- **Theme:** (2) Multi-agent frameworks & orchestration
- **Relevance:** Memory design is one of the recurring hard problems in agent architectures; the "factorize storage from readout from trust" decomposition is a clean pattern worth borrowing.
- **Link:** https://arxiv.org/abs/2608.04530

## 4. Video-DeepResearch: Towards the Next-Generation Multimodal Deepresearch Agent

- **Authors:** Zhen Fang, Yu Zeng, Wenxuan Huang, et al.
- **Summary:** Extends the "deep research" agent pattern (iterative browse + read + synthesize) from text to continuous video by splitting the loop into a perception stage and an exploration stage, and by unlocking tools stage-by-stage rather than exposing the full toolset up front. Trains with SFT followed by GRPO and reports 64.0% on a new Video-DR-Bench, above proprietary baselines.
- **Theme:** (2) Multi-agent frameworks & orchestration
- **Relevance:** Concrete evidence that staged tool unlocking helps convergence in multi-tool agents — a design lever not many papers ablate directly.
- **Link:** https://arxiv.org/abs/2608.03979

## 5. Toward Skill-Native LLMs: Skill Entropy for Benchmarking and Training Long-Horizon Reasoning

- **Authors:** Yinghui He, Ling Yang, Jiarui Liu, et al. (incl. Sanjeev Arora)
- **Summary:** Defines "skill entropy" as a measure of how many distinct reasoning skills a task requires the model to switch between, and builds Skill²-Bench around it. Empirically, model accuracy degrades sharply as skill entropy rises, exposing a switching cost that single-skill benchmarks miss. Also proposes a training recipe biased toward higher-entropy trajectories.
- **Theme:** (1) Core LLM advances — reasoning
- **Relevance:** Gives a principled axis (skill-switching) for evaluating "long-horizon reasoning" beyond raw length or step count.
- **Link:** https://arxiv.org/abs/2608.05139

## 6. ABSeeker: Training Long-Horizon Search Agents via Answer-Backtracked Credit Assignment

- **Authors:** Yijun Lu, Rui Ye, Jiajun Wang, et al.
- **Summary:** Trains long-horizon search agents by backtracking from the final answer to identify which intermediate actions were actually useful, and then rewarding those actions densely instead of only rewarding the terminal outcome. Frames the transformation from sparse trajectory rewards to dense step rewards as an offline analysis step that any RL trainer can consume.
- **Theme:** (1) Core LLM advances — planning & agent RL
- **Relevance:** Directly attacks the sparse-reward problem that keeps most agent RL training brittle at horizon > ~10 steps.
- **Link:** https://arxiv.org/abs/2608.05102

## 7. PAST-Bench: Benchmarking the Foundations of Recursive Self-Improvement in Personal Agents

- **Authors:** Shuhan Xue, Zixin Ding, Yichen Shen, et al.
- **Summary:** Isolates the question "does an agent actually get better when it retains experience?" by holding the base LLM fixed and varying only the memory / procedure-reuse / information-gathering / update mechanisms. Spans 26 scenarios × 204 episodes so each capability can be scored independently. Useful diagnostic for teasing apart "the model learned" from "the harness remembered."
- **Theme:** (1) Core LLM advances — agentic-system evaluation
- **Relevance:** Fills a real evaluation gap: most "self-improving agent" claims conflate memory effects with model effects.
- **Link:** https://arxiv.org/abs/2608.04003

## 8. GDPevo: Evaluating Agent Self-Evolution on Real Business Tasks

- **Authors:** Leijun Zhou, Zhihao Liu, Xiang Qu, et al.
- **Summary:** A benchmark grounded in real enterprise workflows (not synthetic tasks) for measuring whether agents genuinely learn from their own execution history. Reports up to +16.44 pp held-out accuracy improvement from a self-evolution loop over a fixed base model, giving one of the cleaner controlled measurements of the effect on realistic workloads.
- **Theme:** (1) Core LLM advances — agentic-system evaluation
- **Relevance:** Complements PAST-Bench with a business-workflow-flavored setup; taken together, the two give a reasonable picture of the "self-evolution" claim.
- **Link:** https://arxiv.org/abs/2608.03764

## 9. SkillJack: Persistent Skill Backdoors in Self-Evolving Agents

- **Authors:** Zonghao Ying, Xiangfan Wu, Huiyu Wu, et al.
- **Summary:** Attacks the experience-to-skill pipeline that many self-evolving agents use: instead of poisoning weights or prompts, the attacker plants malicious behavior in the reusable skill repertoire the agent builds for itself. Reports that packaging the payload as a "skill" drops detection from 98.5% to 11.4% while keeping attack success at 56–89%. A useful reminder that skill libraries are an attack surface, not just a productivity feature.
- **Theme:** (2) Multi-agent frameworks & orchestration (security-of)
- **Relevance:** The threat model is specific to the exact architectural pattern (agents that write and reuse their own skills) this list has been tracking, so the finding is directly actionable.
- **Link:** https://arxiv.org/abs/2608.03509

## 10. WorldCycle: Self-Verifiable Reinforcement Learning for Long-Horizon Video World Models

- **Authors:** Bohai Gu, Yueyang Yuan, Taiyi Wu, et al.
- **Summary:** Trains long-horizon video world models with a self-verification signal derived from reversible action cycles: apply an action and its inverse and check that the world returns to its prior state. This gives a specification-like check the model can supervise itself against, reducing "state-returning drift" by up to 44%. The domain is video, not code, but the pattern — turn an invariant that must hold into a training signal — is the closest thing in the 48h window to formal-verification-inspired training.
- **Theme:** (3) Spec-driven development & formal verification (adjacent — video domain, not code)
- **Relevance:** Included as the closest theme-3 fit; note the caveat above about the theme-3 gap in this window.
- **Link:** https://arxiv.org/abs/2608.04964
