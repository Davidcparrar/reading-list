## 1. Graph Engineering in the Era of LLM Agents: From Individual Intelligence to System Intelligence
- **Authors:** Yuyuan Feng, Zhishang Xiang, Chaobin Yang, et al.
- **Summary:** The paper argues that once you have a fleet of specialized LLM agents, the interesting design surface is no longer the individual agent but the *graph* connecting them — nodes are heterogeneous agents/tools, edges are communication or dependency links, and the whole thing has to be evolved dynamically as a task unfolds. It proposes graph-engineering primitives for constructing, updating, and pruning such agent graphs, and uses them to organize task decomposition, role assignment, and inter-agent messaging under one abstraction. The contribution is largely a unifying framework and taxonomy that pulls existing multi-agent scaffolds (planner/executor, debate, DAG orchestration) into a common graph vocabulary.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Direct hit on the "coordination + communication protocols + role/tool assignment" bullet; useful as scaffolding for reasoning about any future multi-agent architecture we build.
- **Link:** https://arxiv.org/abs/2608.21156

## 2. PolicyGuide: From Guarding One Action to Guiding the Whole Workflow for Policy-Compliant LLM Agents
- **Authors:** KAIST AI team (submitter: erjui)
- **Summary:** PolicyGuide moves beyond per-tool-call guardrails and treats policy compliance as a workflow-level constraint: given a written policy, it plans and constrains the *sequence* of agent actions so that no reachable trajectory violates the spec, rather than only vetoing individual tool invocations. The system compiles the policy into a workflow-scoped monitor that both guides the planner during execution and rejects continuations that would break invariants downstream. Reported evaluations show that whole-workflow guidance catches violations that action-level guards miss, especially in multi-step tool-use settings.
- **Theme:** Multi-agent frameworks & orchestration (with spec-adjacent verification flavor)
- **Relevance:** Bridges orchestration and formal-ish policy enforcement — exactly the "define correctness of agent outputs" angle we care about, applied to workflows rather than single calls.
- **Link:** https://arxiv.org/abs/2608.19861

## 3. Repo0: Design-Driven Zero-to-All Code Generation
- **Authors:** Silin Chen et al. (Shanghai Jiao Tong University)
- **Summary:** Repo0 targets whole-repository generation from a design specification: instead of iteratively patching, the agent first materializes a design artifact (module boundaries, interfaces, data flow) and then generates all files consistent with it in one coordinated pass. The pipeline uses the design as a shared contract across generation steps so that cross-file references, imports, and API shapes stay coherent — the design is treated as the source of truth, and code is a derivation. Empirically it produces more coherent multi-file repositories than iterative "grow from a seed" agents on their benchmarks.
- **Theme:** Spec-driven development & formal verification for coding
- **Relevance:** Cleanest example this week of design/spec being the *primary* artifact that drives code generation — the exact paradigm we're tracking for spec-driven agentic coding.
- **Link:** https://arxiv.org/abs/2608.19854

## 4. Hierarchical Self-Improvement: A Framework for Task-Specific Evolvable Agent Harnesses
- **Authors:** HKUST team (submitter: TalentZHOU)
- **Summary:** The framework treats the *agent harness itself* (prompts, tool wiring, control flow) as a first-class object that evolves per task family, separating a slow outer loop that mutates the harness from a fast inner loop that solves individual tasks. A hierarchical self-improvement operator proposes edits to sub-components (planner, retriever, verifier) based on trace-level attribution of failures, so improvements accumulate at the right level of the stack instead of at the model weights. Reported results show task-specialized harnesses beat a single monolithic agent when compute is matched.
- **Theme:** Multi-agent frameworks & orchestration (harness architecture)
- **Relevance:** Concrete recipe for treating orchestration itself as the evolvable surface — highly relevant to how we structure and iterate agent architectures.
- **Link:** https://arxiv.org/abs/2608.08466

## 5. FlowEvo: Self-Evolving Agents through the Co-Evolution of Workflows and Executable Skills
- **Authors:** Southeast University team (submitter: LeoYML)
- **Summary:** FlowEvo argues that agent improvement stalls if you evolve *only* workflows (composition without new primitives) or *only* skills (primitives with no reconfiguration), so it co-evolves both: workflows propose new required skills, and newly learned executable skills reshape the space of possible workflows. Each round runs task attempts, mines failure patterns, and either mints a new skill or edits the workflow that failed to reach one. The reported gains suggest co-evolution generalizes to unseen tasks better than either axis alone.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Directly on-theme for "role/tool assignment + agent architectures that improve over time" — a useful counterpart to static workflow libraries.
- **Link:** https://arxiv.org/abs/2607.21596

## 6. AgentMercury: Your Agent Can Synthesize Verifiable Environments for Business Scenarios at Scale
- **Authors:** Minbyul Jeong, Chanwoong Yoon
- **Summary:** AgentMercury flips the usual "hand-craft an env, then train agents" pipeline: it uses an agent to synthesize *executable and automatically verifiable* environments from high-level business scenarios, producing 4,783 training substrates spanning industries. Each generated environment ships with programmatic checks so agent behavior can be scored without human graders, giving a large supply of task instances with ground-truth success predicates. Training on the synthesized substrates measurably improves downstream performance on both enterprise workflows and reasoning benchmarks.
- **Theme:** Spec-driven development & formal verification for coding (verifiable environments as a spec substrate)
- **Relevance:** Interesting angle on "correctness of agent outputs" — bakes checkable predicates into the environment itself rather than the model, which is the shape we want for agent evaluation in coding-adjacent settings.
- **Link:** https://arxiv.org/abs/2608.20634

## 7. MemTrapBench: Benchmarking Cognitive Traps in LLM Memory Use
- **Authors:** ZJUNLP team (submitter: mengru)
- **Summary:** MemTrapBench isolates *failure modes* of long-context and retrieval-augmented LLMs by systematically constructing distractor structures that mimic real memory pitfalls — false-anchor recall, order-based interference, self-consistent-but-wrong context, and similar. Each trap is paired with a matched benign variant so accuracy drops attributable to the trap can be measured cleanly. The reported patterns show that scaling context length alone does not close the gap and that certain traps generalize across model families.
- **Theme:** Core LLM advances (agentic-system evaluation, memory)
- **Relevance:** Fine-grained diagnostic surface for the memory/long-context piece of agentic systems — directly informs how we should stress-test any agent that leans on retrieval or scratchpad memory.
- **Link:** https://arxiv.org/abs/2608.20202

## 8. CLEAR: Continuous Latent Adapter Routing for Utility-Preserving LLM Safety Alignment
- **Authors:** Chengxiao Wang, Enyi Jiang, Xiaojing Liao, Sanmi Koyejo
- **Summary:** CLEAR treats safety alignment as a routing problem: hidden-state gates continuously decide, per token/position, how much of a lightweight safety adapter to mix into the base model, rather than either merging the adapter in fully or gating it on/off at the prompt level. The gate is trained to preserve baseline utility on benign inputs while activating on inputs that need the safety head. Reported results show improved robustness on adversarial prompts with much less collateral utility loss than static merging or LoRA-swap baselines.
- **Theme:** Core LLM advances (PEFT / adapter routing)
- **Relevance:** Non-trivial twist on PEFT — the routing is over *hidden states*, not prompts — which is a pattern worth borrowing for any tunable-per-task capability we bolt onto agents.
- **Link:** https://arxiv.org/abs/2608.21278

## 9. SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science?
- **Authors:** OpenMOSS team (submitter: yxzwang)
- **Summary:** SWE-bench Science ports the SWE-bench methodology to scientific-software repositories, where the "issues" are real engineering tasks in numerical, simulation, and data-processing codebases with their own domain-specific correctness criteria. It builds an executable harness for each task so agents are scored on whether their patches actually pass the project's tests, not on textual similarity to a reference patch. Early results show current coding agents that do well on standard SWE-bench slip meaningfully on scientific repos, exposing a domain-transfer gap.
- **Theme:** Spec-driven development & formal verification for coding (executable spec = the project's tests)
- **Relevance:** Extends the executable-test-as-spec evaluation model into a harder domain — directly relevant to how we measure coding-agent correctness beyond toy repos.
- **Link:** https://arxiv.org/abs/2608.19799

## 10. Every Coin Has Two Sides: On the Dual Nature of Generalization in On-Policy Distillation of Large Language Models
- **Authors:** Zhaoyi Li, Deyang Kong, Yuan Wei, et al.
- **Summary:** The paper dissects on-policy distillation and finds it transfers *reasoning behaviors* from teacher to student more than specific answers, but the effect is asymmetric: the size of the gain depends strongly on whether teacher and student share pretraining lineage. When the pair is well-matched, on-policy distillation lifts reasoning generalization; when it is mismatched, it can inject brittle patterns that hurt out-of-distribution behavior. The takeaway is a set of guidelines for when on-policy distillation is worth the compute versus vanilla SFT.
- **Theme:** Core LLM advances (fine-tuning / distillation)
- **Relevance:** Practical, decision-useful signal on when to reach for on-policy distillation for reasoning — directly informs post-training choices for future agent bases.
- **Link:** https://arxiv.org/abs/2608.16647
