# Reading digest — 2026-08-20

Found 10 paper(s) in the last 48h window.

## 1. SPADE: Self-Play in Adaptive Synthetic Executable Environments
- **Authors:** Bo Liu, Simon Yu, Yiding Jiang, et al.
- **Summary:** SPADE trains a single LLM in a dual role — one head proposes new executable training environments (small tool-using tasks with unit tests), and another head learns to solve them under RL. A regret-style signal steers environment design toward the frontier where the solver is neither trivially winning nor hopeless, so training data self-adapts as the policy improves. On math, science, and code benchmarks the loop lifts average accuracy by ~5 points over static curricula and matches larger models trained on curated data.
- **Theme:** Core LLM advances (reasoning, RL curriculum, tool use).
- **Relevance:** Strong-lab paper (Zettlemoyer, Yejin Choi, Natasha Jaques) that removes hand-curated environments from the RL loop — directly relevant to how post-training is going to look for reasoning/tool agents.
- https://arxiv.org/abs/2608.19197

## 2. Agent Lightning v1.0: Towards Harnessed Agentic RL
- **Authors:** Zhiyuan He, Siwei Zhang, Zhiwen Zhou, et al.
- **Summary:** Microsoft's Agent Lightning turns whatever agent harness you already have (a Python script, a LangGraph, a bespoke loop) into an RL-trainable target by proxying LLM calls inside the harness and reconstructing rollouts from the proxy traces. The framework does not require rewriting the agent as a pure policy, and it exposes standard PPO-style updates plus sandboxed environment orchestration. Applied to a coding agent it reports a 14.6 point gain on SWE-bench Verified with modest data and compute.
- **Theme:** Multi-agent frameworks & orchestration (agentic RL harness / architecture).
- **Relevance:** A production-grade generalization of the "wrap any agent, then RL it" pattern several groups are now converging on — worth reading for the harness/proxy design.
- https://arxiv.org/abs/2608.17528

## 3. LEGO-RL: Harness-Native Reinforcement Learning for Coding Agents
- **Authors:** Yiming Du, Yuxin Jiang, Tao Yuan, et al.
- **Summary:** LEGO-RL keeps a coding agent's real inference harness in the training loop by putting the LLM behind an in-process proxy and running sandboxes for each rollout, so gradients are computed on trajectories that match production execution. The paper argues that mismatch between shortened "training harnesses" and full agent scaffolds is the main reason RL post-training of coding agents transfers poorly, and that harness-native rollouts close most of that gap. Reported gains on SWE-style benchmarks come with modest infra overhead compared with distilled offline pipelines.
- **Theme:** Core LLM advances (RL fine-tuning), with direct coding-agent implications overlapping category 3.
- **Relevance:** Companion in spirit to Agent Lightning; useful contrast between two ways of doing RL through a full harness.
- https://arxiv.org/abs/2608.17393

## 4. Co-RL: Unsupervised Reasoning Emerges from Diverse Cohort in Multi-agent RL
- **Authors:** Yunhao Yang, Yuexin Bian, Yunjie Tian, et al.
- **Summary:** Co-RL trains a cohort of LLM agents cooperatively without ground-truth labels: each agent's reward is derived from peer verification and disagreement across the cohort, which produces a self-supervised signal for reasoning. The authors show the peer-derived reward is well behaved enough to bootstrap chain-of-thought reasoning on both text and vision-language tasks. Empirically, unsupervised Co-RL nearly matches label-supervised RL on several reasoning benchmarks.
- **Theme:** Multi-agent frameworks & orchestration (peer-graded reasoning).
- **Relevance:** Concrete instance of "no labels, just a cohort" — a compelling data-efficiency story for teams that cannot label their own domain.
- https://arxiv.org/abs/2608.17253

## 5. SemaPLC: A Project-Grounded, Verification-Gated Agent Harness for PLC Code Generation
- **Authors:** Yanlun Tu, Huacan Wang, Ziyue Zhou, et al.
- **Summary:** SemaPLC generates PLC (industrial controller) code inside an agent loop that will not emit a candidate until it survives external compilation and live runtime execution against the project's environment. The harness treats the compiler and simulator as first-class critics, iterating on the LLM's output while carrying project-level context (variable tables, IO maps) rather than isolated snippets. Verified pass-rates rise substantially above prompt-only baselines on their PLC benchmark.
- **Theme:** Spec-driven development / formal verification for coding agents.
- **Relevance:** One of the few papers in the 48h window that actually gates generation on external formal-ish checks; the pattern (compile + run + specification-carrying context) transfers directly to non-PLC coding agents.
- https://arxiv.org/abs/2608.18565

## 6. Agentic ESOpt: Fine-Tuning Long-Horizon LLM Agents with Minimal GPU Requirements
- **Authors:** Zhi Zheng, Rongsheng Chen, Yunpeng Ba, et al.
- **Summary:** Agentic ESOpt shows evolution strategies can full-parameter-tune an LLM used as a long-horizon agent while only requiring inference-level GPU memory, since ES needs forward passes rather than backprop through multi-step rollouts. The paper positions ES as more scalable than PPO for very long trajectories where credit assignment and memory blow up. Results across long-horizon agent benchmarks are competitive with, and in some cases exceed, gradient-based RL baselines.
- **Theme:** Core LLM advances (fine-tuning / PEFT alternative for agents).
- **Relevance:** A different post-training axis than the two RL-harness papers above; worth pairing with them to see the space of trade-offs (memory, wall-clock, credit assignment).
- https://arxiv.org/abs/2608.17310

## 7. ASI-Bench: At the Dawn of Artificial Superintelligence
- **Authors:** Junwei Zhou, Zhen Sun, Binyu Li, et al.
- **Summary:** ASI-Bench evaluates how far agents can carry an autonomous scientific research task with progressively less human scaffolding, across 11 domains and lifecycle stages (question, plan, execute, write). It reports large gaps between "with methodological guidance" and "cold start" runs, quantifying how much of current agent performance is really scaffolding rather than initiative. The design produces a clear axis for measuring self-direction rather than just task success.
- **Theme:** Core LLM advances (agentic-system evaluation).
- **Relevance:** Useful as an evaluation frame — separates "the agent finished the task" from "the agent decided what to do." Directly relevant to designing evals for autonomous coding pipelines.
- https://arxiv.org/abs/2608.17271

## 8. SkillGate: Training In-Policy Skill Selection in Long-Horizon Agents
- **Authors:** Qingyao Li, Wenxiang Jiao, Shuai Shao, et al.
- **Summary:** SkillGate isolates the credit-assignment problem for the small number of "skill selection" tokens in a long-horizon agent: outcome reward flows only to the execution tokens of the chosen skill, while the naming/selection tokens are updated with a separate local advantage. This prevents the selector from being drowned out by execution noise and from being punished for correctly picking hard skills that then fail for unrelated reasons. Reported gains are on success rate and on the fraction of exposures to bad skills.
- **Theme:** Core LLM advances (planning / tool selection for agents).
- **Relevance:** Small, precise fix to a real bug in agent RL post-training; the decomposition is generalizable to any hierarchical policy over tool calls.
- https://arxiv.org/abs/2608.18852

## 9. SkillForge: Self-Distilling Agents for Project-Specific Issue Resolution
- **Authors:** Not fully enumerated in the source feed (see arXiv for full list).
- **Summary:** SkillForge lets a coding agent build project-specific "skills" by running on a project, distilling recurring solution patterns from its own trajectories, and reusing them as compressed programmatic knowledge on later issues. The self-distillation avoids per-project fine-tuning while still specializing the agent to a codebase's conventions. On SWE-bench-style project-scoped evaluations, adding the distilled skills yields a ~5.8-point improvement in issue-resolution rate.
- **Theme:** Core LLM advances (agent skill acquisition for coding).
- **Relevance:** Complements SkillGate above — one paper is about learning to pick skills, this one is about creating them without training weights.
- https://arxiv.org/abs/2608.18933

## 10. FM-Bench: A Benchmark for Long-Horizon Management with Competing Agents
- **Authors:** Tianyou Wang, Chongyang Gao, Kezhen Chen, et al.
- **Summary:** FM-Bench asks an LLM agent to run a football club for 20 in-simulator years against other LLM-run clubs, generating a long-horizon competitive decision environment where transfer choices, contracts, and tactics compound over hundreds of turns. The main empirical finding is that raw model scale and token spend do not predict success — behavioral patterns (patience, risk posture, delegation) matter more. The benchmark and traces are released for follow-up.
- **Theme:** Core LLM advances (agentic-system evaluation over long horizons).
- **Relevance:** Rare eval where "just use a bigger model" isn't the answer, and where competing LLM agents create an emergent baseline. Interesting frame for evaluating orchestration/architecture choices, not just base-model quality.
- https://arxiv.org/abs/2608.18423
