## 1. Djinnlang: Higher-Level Programming by Unambiguous Specification with an LLM in the Compiler
- **Authors:** Simon Henniger, Stephen Chong, Nada Amin
- **Summary:** Djinnlang inverts the usual LLM-for-coding relationship: programmers write formal specifications and the compiler invokes an LLM to synthesise an implementation, then uses Dafny to prove the synthesised code matches the spec before accepting it. The authors show the loop is stable enough to self-host parts of the toolchain, giving a concrete route to spec-driven development where the model's output is only trusted after a mechanical proof.
- **Theme:** Spec-driven development & formal verification for coding
- **Relevance:** Strongest match this window — literally embeds an LLM inside a verifying compiler, which is exactly the "define correctness of agent outputs for code" story the digest tracks.
- **Link:** https://arxiv.org/abs/2609.23954

## 2. VSpector: Specification-Driven Bug Detection for RISC-V CPUs
- **Authors:** Tianyu Jia, Zhaoyang Yu, Yuanliang Chen, et al.
- **Summary:** VSpector treats the official RISC-V ISA specification as the oracle for differential testing, avoiding the usual need for a hand-written reference model or bespoke formal properties. The pipeline confirmed 148 known violations and discovered 42 previously unknown bugs across production RISC-V cores, demonstrating that natural-language + machine-readable specs can drive scalable, semi-automated verification.
- **Theme:** Spec-driven development & formal verification for coding
- **Relevance:** Directly operationalises "spec as ground truth" in a domain (silicon) where correctness matters most, and the methodology transfers to agentic code review.
- **Link:** https://arxiv.org/abs/2609.23517

## 3. A Lean and Spec-Driven AI-Assisted Software Development Lifecycle for Applied AI Education
- **Authors:** Andreas Martin, Sandro Schwander
- **Summary:** Proposes a lightweight lifecycle for AI coding agents that pairs repository-local specification files with phase-specific "agent skill" files (planning, coding, review), so each agent invocation is bounded by an explicit spec. Evaluated with student cohorts on business-oriented projects, the approach shows that even minimal spec scaffolding measurably improves the reliability and interpretability of agent-generated code.
- **Theme:** Spec-driven development & formal verification for coding
- **Relevance:** Concrete, low-overhead recipe for putting spec-driven discipline around today's coding agents — practical counterpart to the Djinnlang paper.
- **Link:** https://arxiv.org/abs/2609.24348

## 4. One to More, More to One: Category-Aware Iterative Expert Training for Software Engineering Agents
- **Authors:** Jie Zhao, Ziyu Jiang, Suhang Zheng, et al.
- **Summary:** Notes that repo-level SWE tasks (bug fix, feature add, refactor, migration) progress at very different rates under pooled RL, and proposes a category-aware iterative loop that trains a specialist per category then distils the successful behaviours back into a single generalist. The pipeline reports consistent gains on SWE-bench-style benchmarks over pooled baselines.
- **Theme:** Spec-driven development & formal verification for coding (agentic-coding side)
- **Relevance:** Ties the spec-driven thread to production coding-agent training — clarifies why "one giant coding agent" underperforms per-category experts.
- **Link:** https://arxiv.org/abs/2609.23377

## 5. Harness-Zero: Harness Distillation via Agent-as-Harness
- **Authors:** Haoran Ye, Yuxing Lu, Haonan Dong, et al.
- **Summary:** Observes that the gains from a carefully tuned agent "harness" (prompts, control flow, tools, memory) evaporate the moment you swap harnesses, and proposes distilling the harness-induced behaviour back into the base model's weights so the improvement persists. The method treats the harnessed agent as a teacher and uses on-policy distillation targeted at the tokens that most differentiate harnessed from unharnessed runs.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Directly attacks the biggest weakness of agent frameworks today — non-portability — and gives a concrete recipe for making orchestration gains stick.
- **Link:** https://arxiv.org/abs/2609.24974

## 6. Jev-Mem: System-One-Controlled Agentic Memory for Efficient AI Agents
- **Authors:** Dongming Jiang, Yi Li, Bingzhe Li
- **Summary:** Splits agentic memory into a cheap, always-on "System-1" control plane that filters and routes memory operations, and a more expensive deliberative reasoner that is only invoked when the controller flags a hard case. The design cuts the number of autoregressive memory calls per task substantially while preserving long-horizon task performance.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Memory is the current bottleneck for long-running agents; a dual-process architecture is a clean, reusable pattern for orchestration stacks.
- **Link:** https://arxiv.org/abs/2609.23986

## 7. RRSI: Regularized Recursive Self-Improvement of Agent Harnesses
- **Authors:** Peng Xia, Rujun Han, Zifeng Wang, et al.
- **Summary:** Studies what happens when an agent is allowed to iteratively rewrite its own harness (prompts, tools, control flow) and finds it reliably overfits to the eval set within a few rounds. RRSI adds explicit regularisation — diversity terms and a held-out validation harness — to keep self-improvement generalising rather than memorising, and reports stable gains across several agentic benchmarks.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Self-improving agents are a live research direction; this paper names the overfitting failure mode and offers a concrete fix.
- **Link:** https://arxiv.org/abs/2609.24972

## 8. GameHorizon Suite: Multi-Horizon Data and Evaluation in Gameplay
- **Authors:** Yiran Wang, Xingyilang Yin, Junfu Pu, et al.
- **Summary:** Packages modern video games into a unified data + eval suite that separately measures short-horizon visual understanding, medium-horizon subtask decomposition, and long-horizon goal planning, rather than collapsing them into a single reward. The authors show current agentic models score very differently across horizons, exposing a planning gap that aggregate scores hide.
- **Theme:** Core LLM advances (agentic-system evaluation, planning)
- **Relevance:** A well-designed multi-horizon eval is exactly what's missing when comparing planning-focused LLMs; likely to become a reference benchmark.
- **Link:** https://arxiv.org/abs/2609.25001

## 9. 1% of Tokens Can Be Enough: On Gradient Estimation in On-Policy Distillation
- **Authors:** Huanxin Sheng, Zhiling Ye, Haonan Wang, et al.
- **Summary:** Analyses sparse on-policy distillation and shows the gradient estimator is dominated by a small fraction of high-signal tokens, so uniform teacher supervision wastes compute. Proposes an information-efficiency ratio for selecting which tokens to distil, achieving near-full-distillation quality with ~1% of the teacher forward passes.
- **Theme:** Core LLM advances (fine-tuning / efficient training)
- **Relevance:** Practical fine-tuning result with an immediate cost-quality tradeoff; relevant to anyone doing PEFT-style distillation of larger teachers.
- **Link:** https://arxiv.org/abs/2609.24432

## 10. onPanda: Efficient Annotation of On-Policy Alignment Data for LLMs and Agents via Token-Level Correction
- **Authors:** Lei Yang, Mengyin Liu, Jia Wang, et al.
- **Summary:** Interactive alignment tool where annotators locate offending tokens in a model rollout and edit only those tokens, keeping the rest of the model's sampling distribution intact for downstream RL/PPO training. The paper argues token-level correction gives cleaner, lower-variance preference data than full-response rewrites and demonstrates alignment gains on both chat and agent traces.
- **Theme:** Core LLM advances (fine-tuning / alignment)
- **Relevance:** Alignment data pipelines are the current bottleneck for agent post-training; this is a concrete, low-cost annotation protocol.
- **Link:** https://arxiv.org/abs/2609.24983
