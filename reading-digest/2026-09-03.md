## 1. HarnessDev: Can LLMs Create and Evolve Their Own Agent Harness?
- **Authors:** Yuhao Wu, Jingyuan Zhang, Jiajun Shi, et al.
- **Summary:** Introduces a benchmark that measures whether an LLM, given only a task spec and a starting scaffold, can construct and then iteratively improve the execution harness (tools, planner, verifier) around itself. Models are scored on both the harness code they emit and the downstream task success it produces, exposing a large gap between models that can *write* a harness and models that can *evolve* one across rounds.
- **Theme:** (1) Core LLM — agentic-system evaluation.
- **Relevance:** Directly targets how we should benchmark self-improving agent stacks, which is the eval axis we care about most for agent work.
- **Link:** https://arxiv.org/abs/2609.01437

## 2. Harness-of-Harness: Multi-Day Autonomous Software Development with Continual Improvement
- **Authors:** Haoyang Yan, Min-le Su, Hangfan Zhang, et al.
- **Summary:** Proposes a coding-agent framework that runs plan → code → test loops for days at a time, keeping a versioned project history so later iterations can diff against and repair earlier failures. Reports monotonic quality gains over long horizons on multi-file software tasks where single-shot agents plateau or regress.
- **Theme:** (2) Multi-agent frameworks & orchestration — with heavy overlap into (3) since the correctness signal comes from iterated test/verify passes on generated code.
- **Relevance:** Closest thing in this window to spec-driven coding: correctness of agent output is defined by an evolving test harness rather than by a static prompt.
- **Link:** https://arxiv.org/abs/2609.01481

## 3. Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills (DisCo)
- **Authors:** Jianlyu Chen, Yuyang Hu, Hongjin Qian, et al.
- **Summary:** DisCo mines executable "skills" out of research repositories — invocable procedures with typed inputs, expected outputs, and provenance back to the source repo — and hands the resulting skill library to an autonomous ML-research agent. The distilled skills are shown to lift agent performance on several ML-engineering benchmarks by making tool use compositional instead of ad-hoc.
- **Theme:** (2) Multi-agent frameworks & orchestration — role/tool assignment via a reusable skill library.
- **Relevance:** Attacks the "every agent reinvents its tools" problem, which is a live blocker for multi-agent systems that share a codebase context.
- **Link:** https://arxiv.org/abs/2609.02749

## 4. EarlyEval: Cheaper Agent Evaluation via Early Outcome Prediction
- **Authors:** Yuling Shi, Zhensu Sun, Junsen Dong, Chengcheng Wan, David Lo, Xiaodong Gu
- **Summary:** Trains a lightweight predictor over the agent's intermediate trace (tool calls, partial outputs, self-reflection tokens) that decides when a rollout can be terminated because its final verdict is already knowable. Reports large wall-clock and token savings on standard agent benchmarks with only a small drop in ranking accuracy vs. running every rollout to completion.
- **Theme:** (1) Core LLM — agentic-system evaluation.
- **Relevance:** Practical infrastructure for the eval side of agent development; the same predictor can gate expensive verification steps.
- **Link:** https://arxiv.org/abs/2609.02783

## 5. Cliff: Learning Process Rewards from the First Mistake
- **Authors:** Peixuan Han, Runhui Wang, Ketan Ramaneti, et al.
- **Summary:** A reward-shaping recipe that uses an LLM judge to locate the *first* wrong reasoning step in a rollout, then assigns dense process rewards that penalize post-cliff tokens while preserving credit for the correct prefix. Applied inside RL fine-tuning, it improves math and code reasoning over outcome-only rewards without needing per-step human labels.
- **Theme:** (1) Core LLM — reasoning and fine-tuning.
- **Relevance:** A concrete, cheap way to get process supervision, which is where most reasoning-RL gains are coming from now.
- **Link:** https://arxiv.org/abs/2609.02817

## 6. Language Models Can Control Their Own Attention
- **Authors:** Namgyu Ho, Huzama Ahmad, Woosung Koh, Se-Young Yun, Tal Schuster, Cicero Nogueira dos Santos
- **Summary:** Introduces "Declarative Attention," letting the model emit special spans that name which context regions the next reasoning step should attend to; the runtime then restricts KV-cache reads to those regions. The paper shows large reductions in attention I/O on long-context reasoning benchmarks with negligible accuracy loss and no retraining of the base attention pattern.
- **Theme:** (1) Core LLM — reasoning / long-context efficiency.
- **Relevance:** Model-side lever for making long-horizon agent traces cheaper to run; complements external memory approaches.
- **Link:** https://arxiv.org/abs/2609.02737

## 7. DiagEvo: Diagnosis-Guided Self-Evolution via Hierarchical Error Memory
- **Authors:** Xincheng Wei, Yifan Ding, Yoshua Li, et al.
- **Summary:** Instead of self-improving from generic self-critique, DiagEvo maintains a hierarchical memory of the model's past failure causes and uses it to *steer* which training examples and which correction targets to sample next. A double-confidence filter blocks noisy self-labels, and the resulting training loop keeps improving where prior self-evolution methods plateau.
- **Theme:** (1) Core LLM — fine-tuning / self-improvement.
- **Relevance:** Directly addresses the collapse mode of naive self-training; the error-memory structure looks reusable for agent post-hoc analysis.
- **Link:** https://arxiv.org/abs/2609.00768

## 8. SMELT: Scaling Laws for Compute-Matched MoE Looped Transformers
- **Authors:** Shaowen Wang, Ge Zhang, Kairong Luo, et al.
- **Summary:** Studies looped MoE transformers under a strict compute-matched budget and derives scaling laws for how many loops, how many experts, and what routing style minimize loss. Under the resulting recipe, looped MoE reaches target loss faster than dense or standard-MoE baselines and transfers to downstream tasks.
- **Theme:** (1) Core LLM — architecture / pretraining efficiency.
- **Relevance:** Feeds into what backbones next-gen agent models will be built on; the loop-count knob has direct implications for latency-vs-quality trade-offs.
- **Link:** https://arxiv.org/abs/2609.01343

## 9. From Production Traffic to Post-Training: Building a Self-Hosted LLM That Covers the Corporate Request Mix
- **Authors:** Olga Tsymboi, Dmitrii Stoianov, Ramil Latypov, et al.
- **Summary:** Describes an end-to-end pipeline that turns anonymized production traffic into per-workload GRPO experts (instruction following, function calling, retrieval-QA, etc.) and merges them with SLERP into a single self-hosted model. The merged model beats a much larger baseline on the same corporate-mix eval while remaining deployable on modest hardware.
- **Theme:** (1) Core LLM — post-training / PEFT.
- **Relevance:** A rare, concrete recipe for fine-tuning against real usage rather than a public benchmark; the expert-merging step is the interesting bit.
- **Link:** https://arxiv.org/abs/2609.01572

## 10. EM²Mem: Event-Centric Multimodal Memory for Large Language Models
- **Authors:** Yijun Chen, Yaqi Zheng, Yanya Li, et al.
- **Summary:** Structures long-video / long-history memory around *event anchors*: heterogeneous evidence (frames, transcripts, tool outputs) is bound to a small number of event nodes, and retrieval returns a compact, generation-ready bundle rather than raw chunks. Reports state-of-the-art on long-video QA with substantially lower context cost than flat retrieval baselines.
- **Theme:** (1) Core LLM — memory for long-horizon tasks (with obvious application to multi-agent state).
- **Relevance:** Event-centric bundling is a promising shape for agent working memory; the same anchor idea could organize multi-agent shared state.
- **Link:** https://arxiv.org/abs/2609.00551
