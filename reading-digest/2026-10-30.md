## 1. When Requirements Interact: Scaling Long-Horizon Coding via Interdependent Specifications
- **Authors:** Yishuo Cai, Minzheng Wang, Liang Zhao, et al.
- **Summary:** Introduces CodeSpecWeave, a pipeline that synthesizes long-horizon coding tasks whose specifications depend on one another, so a passing solution must satisfy coupled constraints rather than a single primary goal. A synthesis agent iteratively grows the requirement graph and executable tests while a review agent audits trajectories from multiple models to prune unreliable tests; the resulting 4,670-task corpus and a 100-task benchmark (1,044 specifications) are used for RL training that improves a DeepSWE-v1.1 base over existing SWE RL baselines.
- **Theme:** 3 — spec-driven development for coding.
- **Relevance:** Direct, concrete attack on the "what does correct mean?" problem for coding agents — treating interdependent specifications as training signal and benchmark rather than an afterthought.
- **Link:** https://arxiv.org/abs/2610.40256

## 2. MAS-Loop: Beyond One-Shot Orchestration towards Self-Evolving Multi-Agent Systems
- **Authors:** Hehai Lin, Qi Yang, Chengwei Qin
- **Summary:** Pairs an Orchestrator that builds a multi-agent system with a Refiner that reads the full execution trajectory, localizes a specific failure, and proposes a bounded patch to agents, information flow, or runtime settings; the patched system is re-executed on the same task and compared against the original. The outcome-vs-original delta becomes a shared learning signal, letting the Orchestrator and Refiner co-evolve across iterations, and the authors release MAS-JudgeCorpus of paired executions with trajectory-level labels.
- **Theme:** 2 — multi-agent orchestration.
- **Relevance:** Pushes orchestration past one-shot generation of a MAS graph into a feedback loop where the orchestration policy itself is trained — exactly the kind of coordination/role-assignment work the theme targets.
- **Link:** https://arxiv.org/abs/2610.38946

## 3. PCM: A Proof-Carrying Message Protocol for Verifiable Multi-Agent Communication
- **Authors:** Bravish Ghosh
- **Summary:** Argues that A2A/MCP-style protocols authenticate channels but not senders, so a prompt-injected agent can broadcast fabricated "test passed" or "user approved" facts. PCM attaches to each claim an inclusion proof from an append-only Merkle log the agent cannot write and signed by an external attester, carries authority as narrowable grant chains rooted in a recorded human approval, and defines a typed caveat algebra with replay rules; on a 926-message benchmark containing 712 lies PCM accepts only 10 (all stale evidence) versus 504–712 for modeled competing protocols.
- **Theme:** 2 — multi-agent communication protocols (bridges Theme 3's correctness framing).
- **Relevance:** Formalizes what it means for an agent-to-agent message to be *verifiable*, with proved properties and a hostile-input evaluation — a rare case of multi-agent work that takes correctness semantics seriously.
- **Link:** https://arxiv.org/abs/2610.39109

## 4. UPPAAi: Towards LLM-Assisted Modeling, Verification, Analysis and Synthesis
- **Authors:** Peter Dolog, Kim G. Larsen, Marius Mikučionis, Frederik F. K. Rasmussen
- **Summary:** Wraps the UPPAAL real-time verification toolkit in an LLM dialogue layer that proposes models, explains counterexamples, chooses analysis techniques, and formalizes properties, while delegating the actual verification to UPPAAL via a Tools API bound to the editor and query engine. Seven case studies cover timed automata, stochastic hybrid automata, and strategy learning; the authors note the LLM often suggests UPPAAL features the user had not asked about, improving tool discoverability.
- **Theme:** 3 — formal verification for correctness, LLM as the modeling/spec surface.
- **Relevance:** A concrete pattern for keeping the LLM on the natural-language and modeling side while a trusted verifier owns the correctness verdict — relevant to any team wanting formal guarantees on top of agent output.
- **Link:** https://arxiv.org/abs/2610.40042

## 5. Soei: Structured Observability of Evidence and Intent for Multi-Agent AI Software Engineering
- **Authors:** Mohammed Nayeem Khan, K S Sarun Kumar
- **Summary:** Audits 45 real coding-agent sessions (~102K records, ~20.6K tool executions) and finds that 23.4% of code-editing episodes end with no independent check and 57.8% of agent-marked completions have no proof between the edit and the tick. Proposes Soei: an acknowledgement-aware event schema, a hash-chained local ledger, a W3C PROV-aligned provenance graph, and a verification layer that keeps "claimed complete" strictly separated from "proven complete," benchmarked at ~126K events/sec with tamper detection and deterministic replay.
- **Theme:** 3 — spec/evidence-driven correctness for coding agents (overlaps Theme 2).
- **Relevance:** Treats "did the agent actually verify this?" as a first-class, observable property with a tamper-evident ledger; directly on-topic for defining correctness of coding-agent outputs.
- **Link:** https://arxiv.org/abs/2610.39468

## 6. Investor's Last Exam: Can AI Agents Do Equity Investment Without Seeing the Future?
- **Authors:** Huangfei Jiang, Anning Hu, Kai Sheng, et al.
- **Summary:** Builds an equity-research benchmark with buy-side investors and fund managers, backed by a versioned financial database of 3.43M document versions whose validated timestamps enforce point-in-time retrieval so agents cannot leak future knowledge. The 86-assignment evaluation couples research quality, forecast accuracy, and simulated investment P&L via dependency graphs that tie each scoring criterion to its sources and assumptions; frontier models top out at ~68/100 overall but only ~52/100 on Forecast & Model, surfacing a gap between research polish and predictive skill.
- **Theme:** 1 — agentic-system evaluation.
- **Relevance:** Rigorous counter-example to leaky agent benchmarks; the time-frozen database and dependency-graph scoring are reusable patterns for anyone evaluating agents whose outputs depend on temporal evidence.
- **Link:** https://arxiv.org/abs/2610.38342

## 7. Multi-Token Prediction Done Right
- **Authors:** Jayden Teoh
- **Summary:** Decomposes the standard Multi-Token Prediction cross-entropy gradient into a useful KL self-distillation component (pulling each MTP head toward the model's own next-token distribution) and a residual with low signal-to-noise ratio that interferes with learning as scale grows. Introduces a straight-through gradient-recovery trick that reconstructs the KL term exactly from cross-entropy gradients when heads share a linear output projection, yielding Soft-MTP — a parameter-free, overhead-free one-line change that improves next-token perplexity, speculative decoding speed, zero-shot accuracy, and post-fine-tune math/code scores from 167M up to 1.2B parameters.
- **Theme:** 1 — core LLM pretraining advance.
- **Relevance:** Low-risk, high-leverage pretraining fix with implications for both throughput (speculative decoding) and reasoning quality — likely to propagate quickly into open training stacks.
- **Link:** https://arxiv.org/abs/2610.38331

## 8. EpiAgent: Epistemic Self-Play for LLM Agents
- **Authors:** Xuanfa Jin, Xinyu Cui, Zhijian Ma, et al.
- **Summary:** Adds an explicit, trainable epistemic layer that maintains beliefs about other agents' private information and fuses them with the agent's own context into an epistemic state; the policy is split into Epistemic Update and Action Planning stages and solved as a bi-level problem via self-play, with an intrinsic reward that scores how well inferred beliefs predict later observations. Evaluations on mixed-motive and competitive multi-agent settings show gains over prompting and RL baselines, with ablations attributing the lift to dedicated belief training rather than extra compute.
- **Theme:** 1 (agentic reasoning), bridging Theme 2.
- **Relevance:** Rare, principled take on theory-of-mind for LLM agents with a clean training objective — a plausible building block for multi-agent coordination that must handle hidden information.
- **Link:** https://arxiv.org/abs/2610.40227

## 9. A-RSI: Adaptive Task Refresh for Zero-Data Multimodal Self-Improvement
- **Authors:** Yu Liu, Youxing Li, Yuedong Tan, et al.
- **Summary:** Argues that recursive self-improvement is bottlenecked less by *what* training experience to generate and more by *when* current experience has gone stale; A-RSI monitors reward variance and running accuracy in training logs and triggers a task-pool refresh when the learning signal flattens, without touching validation or test splits. Tasks are drawn from a static library of model-authored programs that emit multimodal questions with checkable answers, so no human labels or external data are used, and refresh/reward rules are machine-audited; on an 11-benchmark suite the average rises from 57.77 to 61.05 after 800 fresh tasks.
- **Theme:** 1 — fine-tuning and self-improvement loops.
- **Relevance:** Treats the "when to refresh" decision as a first-class part of the self-improvement loop with an auditable trigger — a reusable idea even outside multimodal settings.
- **Link:** https://arxiv.org/abs/2610.38568

## 10. Agent Transfer Protocol: Server-Mediated Agent-to-Agent Communication Architecture for the Agentic Web
- **Authors:** Yuqi Qiu, Zuyao Xu, Lu Sun, et al.
- **Summary:** Proposes ATP, a cross-organization agent-communication protocol built around administrative domains with stable logical-agent addresses and signed-envelope mediation by domain servers, so messages persist to offline recipients and sending-domain signatures stay independently verifiable long after the originating agent instance is gone. A prototype runs a controlled cross-organization LLM workflow through instance replacements and outages, with mechanism checks and latency measurements that quantify the overhead of server mediation.
- **Theme:** 2 — multi-agent communication / agent architecture.
- **Relevance:** Treats durability and provenance of inter-agent messages as protocol concerns rather than application concerns; complements PCM (#3) by addressing *routing/persistence* where PCM addresses *claim verifiability*.
- **Link:** https://arxiv.org/abs/2610.38398
