## 1. RepoFactory: From Repositories to Training Environments — Scaling Long-Horizon Coding Agents with an Environment Evolution Loop
Authors: Yang Tian, Tianyu Zheng, Xiyuan Yang, et al.
Summary: Converts 10,159 real GitHub repositories spanning 17 domains into verifiable, task-executable training environments for long-horizon coding agents, so correctness can be judged against the repo's own tests rather than a static leaderboard. An "Environment Evolution Loop" uses proxy agent feedback to iteratively improve each environment's training signal (coverage, reward density, specification clarity), closing the gap between synthetic SWE-style benchmarks and real codebases.
Theme: (3) Spec-driven development & formal verification for coding.
Relevance note: Directly aligned with executable-specification based correctness checking for coding agents — the environment itself becomes the correctness spec.
Link: https://arxiv.org/abs/2611.21152

## 2. SilentGuard: Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures
Authors: Sajib Acharjee Dip, Brian Ouyang, Lala Motlhabi
Summary: Introduces a harness-level enforcement layer that attaches invariants (type, range, structural and relational properties every correct response must satisfy) to each tool/API call an agent makes, and withholds any value that violates them before it reaches the agent's reasoning context. Across seven open models and seven fault classes, silent-failure acceptance drops from 74.0% to 1.7% without touching the underlying model.
Theme: (3) Spec-driven development & formal verification for coding (invariant checking on tool outputs is a formal correctness mechanism for agent I/O).
Relevance note: A concrete, deployable example of using declarative correctness specifications to validate agent intermediate state — exactly the pattern spec-driven development advocates for.
Link: https://arxiv.org/abs/2611.20595

## 3. Accelerate Bench: Evaluating Agents for Application-Level Program Optimization
Authors: Bowen Liu, Yuhan Li, Nuo Chen, Weile Luo, Miao Peng, et al.
Summary: A 32-task benchmark for coding agents in which the agent must take a working C/C++ application and produce a faster-but-still-correct version; scoring combines a correctness oracle (functional equivalence against the reference) with measured end-to-end speedup. The dual metric exposes agents that optimise aggressively but silently change observable behaviour, which single-metric SWE benchmarks miss.
Theme: (3) Spec-driven development & formal verification for coding.
Relevance note: A rare benchmark that treats functional equivalence as a hard correctness spec rather than token-overlap — useful shape for anyone building agentic refactor/optimisation tooling with verification in the loop.
Link: https://arxiv.org/abs/2611.20882

## 4. Heave-Ho: Decentralised Long-Horizon Multi-Humanoid Collaboration
Authors: Ting-Hsuan Chen, Siheng Zhao, Han Jiang, Qi Pan, Louison Lu, et al.
Summary: A fully decentralised framework in which multiple humanoid robots plan and execute long-horizon whole-body loco-manipulation using only local observations plus natural-language speech as the inter-agent coordination channel. A VLM planner per robot assigns and renegotiates roles on-the-fly; empirically beats centralised baselines on multi-hour cooperative tasks.
Theme: (2) Multi-agent frameworks & orchestration.
Relevance note: Clean example of language as the communication protocol in a multi-agent system, with explicit role assignment and renegotiation — directly on-topic for orchestration research.
Link: https://arxiv.org/abs/2611.22275

## 5. VideoNexus: Video Perception Beyond the Reasoning Context
Authors: Yancheng Long, Xuanyu Zheng, Wei Chen, Luoyuan Zhang, Haoyang Xu, Bin Wen, Tingting Gao
Summary: Training-free orchestration framework where a planner LLM dispatches specialised perception sub-agents (detection, OCR, tracking, temporal grounding) that each return compact, timestamped "evidence packets" rather than raw frames, keeping the planner's context small. Reaches 88.6% on LVBench without any additional training and generalises across backbones.
Theme: (2) Multi-agent frameworks & orchestration.
Relevance note: A planner-with-typed-tool-agents pattern that cleanly separates perception from reasoning — a reusable orchestration recipe beyond video.
Link: https://arxiv.org/abs/2611.21392

## 6. Do LLM Agents Still Need to Be Told How to Self-Improve?
Authors: Shobhita Sundaram, Cansu Sancaktar, Phillip Isola
Summary: Tests whether frozen frontier LLM agents, given only a compute budget and a toolbox, can design their own self-improvement loops in interactive game environments without any human-authored curriculum. Finds that sufficiently capable models do self-improve, and that the natural-language "self-improvement artefacts" they write transfer to unseen tasks including 3D navigation — evidence that explicit meta-prompts may be becoming unnecessary.
Theme: (1) Core LLM advances — agentic-system evaluation & planning.
Relevance note: Important negative result for a lot of current "agent harness" research: capable models may need less scaffolding than the field assumes.
Link: https://arxiv.org/abs/2611.23219

## 7. Regularised Score Centering: Reverse-KL-Regularised Off-Policy RL for Agentic LLMs
Authors: Hao Bai, Chenlu Ye, Xuanchang Zhang, Aviral Kumar, Tong Zhang
Summary: Adds a reverse-KL penalty to the score-centering off-policy RL objective so the policy stays close to the behaviour distribution while still exploiting asynchronous rollouts, avoiding the mode-collapse that plain off-policy RL hits on long-horizon agent tasks. Reports a 14.3-point improvement on AppWorld and gains on math and BabyAI with smaller rollout budgets.
Theme: (1) Core LLM advances — RL/fine-tuning for agentic reasoning.
Relevance note: Practical, drop-in RL stabiliser for people already running async off-policy agent training; the paper's gains are on exactly the agentic benchmarks that most evaluate against.
Link: https://arxiv.org/abs/2611.21791

## 8. M3OPD-Reasoner: An Open Recipe for Post-Training Multimodal Reasoning via Multi-Teacher On-Policy Distillation
Authors: Nguyen Quang Trung, Hoang Phan, Shuo Sun, Longyin Zhang, AiTi Aw
Summary: Releases a reproducible post-training pipeline that distils several domain-specialised vision-language teachers (image-STEM, image perception, video reasoning) into one student with on-policy trajectories, followed by RL on the fused student. Ships datasets, code and checkpoints — notable for the open recipe rather than a new model alone.
Theme: (1) Core LLM advances — fine-tuning/PEFT and reasoning.
Relevance note: Concrete, replicable multi-teacher distillation recipe — the "teachers → student → RL" loop is a pattern worth copying for domain-specialised agents.
Link: https://arxiv.org/abs/2611.23034

## 9. K2-Horizon: A Frontier Fleet of Open-Source Language Models
Authors: K2 Team, Zhengzhong Liu, Haonan Li, Xuezhe Ma, et al.
Summary: Open-sources six models from 0.9B to 375B-A23B MoE trained with a new attention variant and a decoding scheme the authors call "horizon decoding" aimed at long-form planning. Reports competitive scores on reasoning and agent benchmarks against closed frontier models at a reportedly much lower training cost.
Theme: (1) Core LLM advances — architectures, reasoning & planning.
Relevance note: Rare fully-open frontier-scale release with architectural novelty rather than yet another post-training recipe; worth tracking as a research substrate.
Link: https://arxiv.org/abs/2611.21003

## 10. Weight-Space Programming Doesn't Need Transformers
Authors: Hyunjong Ok, Jaeho Lee
Summary: Asks LLMs to write neural-network weights directly (no gradient training), and finds that when free to choose the architecture, the models consistently emit sparse tables and associative-memory layouts that use orders of magnitude fewer parameters than the Transformer they are hosted in. Suggests that the "optimal" architecture a capable model would reach for is not the one we train it on — a provocative data point for architecture research.
Theme: (1) Core LLM advances — architectural exploration.
Relevance note: Short, high-signal result that reframes what "programmable weights" means; useful fodder for architecture debates on the team.
Link: https://arxiv.org/abs/2611.22055
