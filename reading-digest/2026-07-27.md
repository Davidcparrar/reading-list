## 1. Agentic Context Management: Solving Agent Memory and Cost by Treating Them as Lifecycle and Architecture Problems
- **Authors:** Gaurav Dadhich
- **Summary:** Reframes recurrent production-agent failures (context bloat, prompt drift, runaway token cost) as a memory-lifecycle problem rather than a prompt-engineering one. Proposes an *Agentic Context Management* discipline built around five primitives (isolation, compaction, offloading, retrieval, versioning) and reports a validated compaction strategy that keeps total token cost approximately linear in trajectory length while preserving reasoning fidelity.
- **Theme:** Memory for LLMs and agents
- **Relevance:** Direct, engineering-grounded treatment of long-term/working-memory management for agents — exactly the "memory > multi-agent > core LLM" priority.
- **Link:** https://arxiv.org/abs/2607.21503

## 2. Towards Trustworthy and Cost-Efficient Data Integration: From Naïve RAG to Agentic RAG
- **Authors:** Chuangtao Ma, Arijit Khan
- **Summary:** Charts the move from single-shot retrieval-augmented generation to an *Agentic RAG* framework that pairs adaptive retrieval with iterative multi-agent reasoning, batched execution, and a graph-based memory substrate. Shows the graph memory + coordinated agents combination improves answer trustworthiness on integration tasks while cutting per-query compute versus repeated naïve RAG calls.
- **Theme:** Memory for LLMs and agents (+ multi-agent orchestration)
- **Relevance:** Sits at the memory ↔ multi-agent intersection — graph memory as shared state across cooperating retrievers.
- **Link:** https://arxiv.org/abs/2607.22319

## 3. AREX: Towards a Recursively Self-Improving Agent for Deep Research
- **Authors:** Shuqi Lu, Chaofan Li, Kun Luo (BAAI)
- **Summary:** Builds a deep-research agent around the *asymmetry between discovering and verifying* — cheap verifiers gate expensive search — and layers explicit context management on top so state survives across long research horizons. Combined with a specialised training recipe, the agent outperforms comparable baselines across several deep-research benchmarks.
- **Theme:** Memory for LLMs and agents (long-horizon context/state management)
- **Relevance:** One of the few recent recipes to explicitly manage agent memory across multi-hour research trajectories.
- **Link:** https://arxiv.org/abs/2607.21461

## 4. IDEAgent: Agentic Quality-Diversity Search for Research Idea Generation
- **Authors:** Varun Gumma, Navonil Majumder, Soumitra Sinhahajari, Soujanya Poria
- **Summary:** Runs research-idea generation as a quality-diversity search over a population of agent-authored idea *lineages*: dedicated critic/generator/scorer roles produce multi-objective feedback (quality) while a sequential memory of prior ideas and explicit pairwise comparisons enforce diversity. The resulting Pareto front is broader and higher-scoring than single-agent or plain best-of-N baselines.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Clean role-assignment example (generator ↔ critic ↔ scorer) with population-level memory driving exploration.
- **Link:** https://arxiv.org/abs/2607.22375

## 5. Skill Self-Play: Pushing the Frontier of LLM Capability with Co-Evolving Skills
- **Authors:** Siyuan Huang, Pengyu Cheng, Haotian Liu, et al.
- **Summary:** Argues that self-evolutionary training faces a diversity ↔ verifiability trade-off, and threads it by treating individual *skills* as the unit of self-play: each skill has a verifiable execution scenario while a dynamic router keeps the overall task distribution wide. A proposer/solver/skill-controller loop trained with RL yields sustained capability gains on tool-use and reasoning benchmarks without collapsing to easily-verifiable tasks.
- **Theme:** Multi-agent frameworks & orchestration (also core LLM — RL post-training)
- **Relevance:** Concrete proposer/solver/controller architecture — a clean multi-role coordination pattern.
- **Link:** https://arxiv.org/abs/2607.22529

## 6. SceneActBench: Can Agents Act on the 3D Scenes They See?
- **Authors:** Yifei Zhao, Xiangxin Zhou, Wenhao Yang, et al.
- **Summary:** A benchmark that closes the loop between perception and action for VLM agents across five 3D scene-manipulation tasks in a single agent-environment interface. Task-specific geometric metrics expose that current VLM agents perceive the scene competently but degrade sharply once they must plan multi-object actions on top of that perception.
- **Theme:** Multi-agent / agentic-system evaluation
- **Relevance:** New, non-toy benchmark for the perception → planning → action loop that most agent frameworks now claim to handle.
- **Link:** https://arxiv.org/abs/2607.22393

## 7. OpenForgeRL: Train Harness-native Agents in Any Environment
- **Authors:** Xiao Yu, Baolin Peng, Ruize Xu
- **Summary:** Attacks the *train-deploy mismatch* that plagues agent RL — models trained on synthetic wrappers underperform once inside the real harness — by making the deployment harness itself the training environment. Reports gains on text-based tool-use tasks and multimodal GUI-agent tasks with the same recipe.
- **Theme:** Multi-agent frameworks & orchestration (agent training infra)
- **Relevance:** Practical answer to a well-known agentic-RL failure mode; complements Molt (#8) as an orchestration-layer story rather than a training-stack one.
- **Link:** https://arxiv.org/abs/2607.21557

## 8. Molt: A Scalable PyTorch-Native Training Framework for Agentic Reinforcement Learning
- **Authors:** Jian Hu, Huiying Li, Hao Zhang, et al.
- **Summary:** Delivers a PyTorch-native agentic-RL training stack whose main design goal is *readable*, minimally-modified algorithm code that still matches Megatron-based systems on throughput. The end-to-end traceable flow lowers the cost of prototyping new agentic-RL algorithms without paying a performance tax.
- **Theme:** Core LLM advances (fine-tuning / RL infrastructure for agents)
- **Relevance:** Infrastructure paper that materially lowers the entry bar for agentic-RL research — a repeated user interest area.
- **Link:** https://arxiv.org/abs/2607.21653

## 9. Multi-Head Latent Control: A Unified Interface for LLM Agent Decision Making
- **Authors:** Amirhosein Ghasemabadi, Ruichen Chen, Bahador Rashidi, Di Niu
- **Summary:** Adds a lightweight side-network that reads the LLM's hidden-state trajectory and emits two decision signals per turn: a *Capability Head* that estimates whether the model is competent for the current query, and a *Resolution Head* that picks among clarify / call-tool / abstain / answer. The interface is trained separately from the base LLM, so the same controller generalises across models and tasks without extra fine-tuning.
- **Theme:** Core LLM advances (agent decision-making / planning)
- **Relevance:** Concrete recipe for a decision layer that many multi-agent frameworks currently hand-roll — nice complement to #4/#5/#7.
- **Link:** https://arxiv.org/abs/2607.14277
