## 1. SpecEngineeringBench: Evaluating Coding Agents as Autonomous Specification Engineers
- **Authors:** Xingjian Wang, Shijian Wang, Minghao Liu, et al.
- **Submitted:** 2026-11-24
- **Theme:** (3) Spec-driven development & formal verification for coding
- **Summary:** The authors build a benchmark of 100 real Python repository instances that force a coding agent to act as a specification engineer: starting from informal requirements, the agent must localize the relevant modules, author executable tests that capture the intended behavior, and flag defects — all without ground-truth hints. They separate three sub-skills (localization, test synthesis, bug detection) and report that recall collapses as localization granularity moves from file to function level, suggesting current agents write tests against the wrong anchor more often than against the wrong intent.
- **Relevance:** Directly operationalizes "spec-driven development" as a measurable agent capability instead of a slogan, and it grades the test-synthesis step that most "agent writes verified code" pipelines hand-wave past.
- **Link:** https://arxiv.org/abs/2611.32973

## 2. CUA-SEE: Self-Evolving Evaluation Environments for Computer-Use Agents
- **Authors:** Wenhao Wang, Panrong Tong, Quyu Kong, et al.
- **Submitted:** 2026-11-23
- **Theme:** (3) Spec-driven development & formal verification for coding (verifier synthesis), with a (1) agentic-evaluation overlap
- **Summary:** CUA-SEE closes an evaluation loop by generating new tasks and matching executable verifiers from the rollouts of the agent under test, rather than relying on static ground-truth traces. Each verifier is a small program that decides pass/fail for a task instance, so the benchmark co-evolves with the agent's demonstrated capability ceiling and can be re-run to probe where the agent breaks.
- **Relevance:** The executable-verifier synthesis half is a direct spec/verification contribution — it treats "did the agent succeed" as a decidable predicate the system writes, not a human label — which is the pattern spec-driven agent coding needs at scale.
- **Link:** https://arxiv.org/abs/2611.30962

## 3. ACAP: Asynchronous Coding Agents for Efficient Robot Control
- **Authors:** Zexin He, Rui Li, Yushi Lan, et al.
- **Submitted:** 2026-11-23
- **Theme:** (2) Multi-agent frameworks & orchestration
- **Summary:** Instead of one monolithic policy, ACAP runs a persistent team of coding agents, one per control group (e.g. arm, gripper, base), coordinated by a hyper-agent that assigns goals and arbitrates conflicts asynchronously. Real-world experiments on a manipulation platform show lower wall-clock cost per task than a single-agent coding baseline, and the group boundary gives the hyper-agent a natural interface for role and tool assignment.
- **Relevance:** A concrete role-assignment protocol with asynchronous execution — exactly the coordination-and-communication slice of theme 2 — and the "one coding agent per subsystem" factoring generalizes beyond robotics.
- **Link:** https://arxiv.org/abs/2611.31205

## 4. StateWeaver: Multi-Agent Coordination of Story-State Transitions for Long-Horizon Video Generation
- **Authors:** Modi Jin, Xuying Zhang, Yijing Guo, et al.
- **Submitted:** 2026-11-25
- **Theme:** (2) Multi-agent frameworks & orchestration
- **Summary:** StateWeaver decomposes long-horizon generation into specialized agents — a state tracker, a planner, a memory manager, and shot-level renderers — that share a hierarchical scene memory so characters, objects, and relations stay consistent across shots. The contribution worth copying is the explicit state-transition protocol between agents rather than the particular video output, since the same pattern applies to any long-horizon generation task.
- **Relevance:** Clean example of an inter-agent state protocol with a memory tier; the architecture is more informative than the video-specific benchmark it targets.
- **Link:** https://arxiv.org/abs/2611.34290

## 5. CoT-Proxy: Cross-Format Transfer for Distilling Long-Horizon Policies
- **Authors:** Dawid J. Kopiczko, Tijmen Blankevoort, Yuki M. Asano
- **Submitted:** 2026-11-24
- **Theme:** (1) Core LLM — PEFT / distillation for agents
- **Summary:** Shows that a student can be distilled from a teacher using only the teacher's action trajectories, with an empty placeholder for the teacher's hidden chain-of-thought, optionally filled by short summaries. The method lifts AppWorld and SWE-bench success rates even when the teacher is closed-source and never exposes its reasoning, which turns long-horizon agent distillation into an actions-only problem.
- **Relevance:** Practical PEFT recipe for agentic coding settings where only API actions are observable; the empty-reasoning-slot trick is a clean ablation of what reasoning distillation actually buys.
- **Link:** https://arxiv.org/abs/2611.33148

## 6. Lazy Agents Answer Against Their Own Beliefs: RL with Verifiable Beliefs (RLVB)
- **Authors:** Richmond Sin Jing Xuan, Peilin Feng, Wenbin Wang, et al.
- **Submitted:** 2026-11-24
- **Theme:** (1) Core LLM — reasoning / RL
- **Summary:** The authors observe that RL-trained agents often commit to an answer before their internal belief is confident, then rationalize. RLVB adds a reward structure that pays for continued exploration while the belief remains uncertain and pays for committing once evidence is sufficient — implemented without a judge model or learned reward — and reports improvements on reasoning benchmarks where premature commitment is the main failure mode.
- **Relevance:** Targets a specific, diagnosable reasoning failure with a training signal that needs no additional reward model — a cheaper lever than scaling verifier critics.
- **Link:** https://arxiv.org/abs/2611.32884

## 7. DRBench Pro: A Knowledge-Centric Benchmark for Professional Deep Research Agents
- **Authors:** Han Huang, Yuchen Yan, Xingyu Wu, et al.
- **Submitted:** 2026-11-25
- **Theme:** (1) Core LLM — agentic-system evaluation
- **Summary:** Evaluates 16 deep-research agents on 144 professional research tasks using a "knowledge tree" scoring scheme: each ground-truth report is decomposed into required claims arranged by breadth and depth, and agent outputs are credited for coverage along both axes. The breadth/depth split exposes agents that superficially touch many topics without ever drilling in, and vice versa.
- **Relevance:** Moves deep-research evaluation past single rubric scores to a shape-aware metric, which is the right abstraction for comparing orchestration strategies.
- **Link:** https://arxiv.org/abs/2611.34852

## 8. ICLWorld: Benchmarking In-Context Learning of Agents from Digital to Physical Worlds
- **Authors:** Qingle Liu, Jieming Li, Pei-lin Li, et al.
- **Submitted:** 2026-11-24
- **Theme:** (1) Core LLM — reasoning / agentic evaluation
- **Summary:** Builds an online benchmark where agents must learn counter-intuitive rules from in-context demonstrations and then act accordingly, across both computer-use and embodied settings. The headline finding is a large knowing/doing gap — agents often state the rule correctly when asked yet still act as if the rule did not apply.
- **Relevance:** Isolates the reasoning-to-action transfer failure that hurts most agent deployments and gives a quantitative wedge between verbalization and behavior.
- **Link:** https://arxiv.org/abs/2611.32649

## 9. VibeVideoAgent: Closing the Perceptual Loop for Code-Driven Video Generation
- **Authors:** Xuanyu Zheng, Luoyuan Zhang, Yancheng Long, et al.
- **Submitted:** 2026-11-25
- **Theme:** (2) Multi-agent frameworks & orchestration (coding agent + perception agent)
- **Summary:** A training-free system in which a coding agent writes rendering programs and a separate multimodal perception agent inspects each draft frame-by-frame, feeding back concrete corrections the coder applies. The split keeps generation and verification in different model roles, which the authors show improves audiovisual synchronization relative to a single agent trying to self-critique its own code.
- **Relevance:** Clean instance of generator/critic separation at the agent-architecture level — a transferable pattern for any code-producing agent that needs out-of-band verification.
- **Link:** https://arxiv.org/abs/2611.34237

## 10. OS-Omni: Benchmarking Generalist Computer-Using Agents on Long-Horizon Workflows Across Platforms
- **Authors:** Hui Shen, Yunta Hsieh, Jianing Ma, et al.
- **Submitted:** 2026-11-25
- **Theme:** (1) Core LLM — agentic-system evaluation
- **Summary:** A live benchmark spanning six operating systems and mobile platforms with long-horizon workflows that cross app boundaries. The top-scoring agent reaches 68.5% while humans reach 77.3%, with the agent-human gap widening sharply on iOS and macOS, suggesting platform-specific grounding (not planning) is the current bottleneck.
- **Relevance:** Cross-platform evaluation at realistic workflow length — useful for separating planner quality from UI grounding when comparing agent systems.
- **Link:** https://arxiv.org/abs/2611.34232
