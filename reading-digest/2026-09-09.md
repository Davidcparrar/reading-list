## 1. Procedural Graphs: Self-Evolving Execution Structures for LLM Agents
- **Authors:** Yuxing Lu, Yicheng Chen, Shanchan Wu, et al.
- **Summary:** The authors propose representing an agent's procedural knowledge as a directed graph of action triplets that a "guidance model" localizes to produce step-level situational cues rather than hard-coded plans. A refiner LLM continually rewrites the graph by contrasting successful and failed trajectories, so the execution structure grows from a minimal skeleton and can surpass hand-engineered playbooks across several long-horizon agent benchmarks.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance note:** Directly attacks orchestration of long-horizon LLM agents with a self-evolving control structure — the kind of framework primitive the reading list follows.
- **Link:** https://arxiv.org/abs/2609.09153

## 2. NeoHorse-1: Towards Recursive Self-Improvement via Agentic Post-Training with Routing Harness
- **Authors:** NeoHorse Team, Guoliang Cao, Guohao Dai, et al.
- **Summary:** NeoHorse-1 pairs a heterogeneous pool of models with an intelligent router that logs capability demand and interaction traces, then feeds those traces back through structural validation, semantic evaluation, and a three-stage routing-guided distillation curriculum. The resulting post-training loop lifts macro-average scores from 58.94 → 64.87 (4B) and 65.60 → 69.04 (9B) across eleven benchmarks, giving a concrete recipe for recursive agentic self-improvement.
- **Theme:** Multi-agent frameworks & orchestration + core LLM post-training
- **Relevance note:** A rare full-stack instantiation of "trajectory-in, model-out" agentic post-training with published numbers — useful anchor for evaluating agentic-system training claims.
- **Link:** https://arxiv.org/abs/2609.08183

## 3. Omni Interaction Agent Technical Report (Gander)
- **Authors:** Orantqing, Shengpeng Ji, Junlong Tong, et al.
- **Summary:** Gander is a streaming Thinker–Talker architecture split into a "Cerebellum" that handles real-time perception, speech, and interruption and a "Brain" that runs slower deliberative reasoning, communicating through a chunk-level token stream. The design lets one system take continuous video/speech/text input and simultaneously act, converse, and delegate — a concrete example of role-partitioned multi-agent architecture inside a single model stack.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance note:** Novel role/tool assignment pattern (fast-loop vs. slow-loop agent) applied to a single unified model, informative for agent architecture design.
- **Link:** https://arxiv.org/abs/2609.08977

## 4. Miles v0.1: Production-Level Post-Training
- **Authors:** RadixArk, Tom Chen, Mao Cheng, et al.
- **Summary:** Miles is a full-stack post-training system whose training loop is built around a "verified / clean / customizable" component principle and supports LoRA-RL, on-policy distillation, and SFT under one interface. The report walks through a case study of fully asynchronous agentic RL on GLM-5.2 (744B-A40B) driving terminal-use coding tasks across 64 GB300 GPUs, giving one of the first public looks at production agentic-RL plumbing.
- **Theme:** Core LLM (post-training, PEFT, agentic-system evaluation)
- **Relevance note:** Concrete engineering blueprint for asynchronous agentic RL on coding tasks — matches the practical fine-tuning/PEFT priority.
- **Link:** https://arxiv.org/abs/2609.08368

## 5. Eliciting Weak-to-Strong Generalization with On-Policy Reverse Distillation
- **Authors:** Youngrok Park, Sangmin Bae, Hojung Jung, et al.
- **Summary:** The authors invert on-policy distillation: instead of pulling a student toward a stronger teacher, they measure how a strong candidate's policy shifts on student rollouts and amplify only the updates that the verifier confirms are improving. This keeps the standard policy-optimization fixed points intact while letting the student exceed its weak supervisor faster than existing RL or distillation baselines, in both successive-transfer and multi-teacher regimes.
- **Theme:** Core LLM (fine-tuning / weak-to-strong post-training)
- **Relevance note:** Clean method contribution to a live PEFT problem (verifier-shaped distillation) with a proof-of-concept beyond the teacher.
- **Link:** https://arxiv.org/abs/2609.08798

## 6. Online Draft Co-Training for Speculative Decoding in Large-Scale, Long-Context RL Post-Training
- **Authors:** Zili Wang, Zhaopeng Qiu, Yuekai Zhang, et al.
- **Summary:** The paper addresses the two practical blockers of applying speculative decoding inside long-context RL post-training loops: expressing branched attention inside standard tensor-parallel frameworks and shipping target features across pipeline stages, which they solve with a merged rank-local branch attention kernel and a feature-transport channel called TapChannel. Co-trained drafts stay aligned with the base policy while cutting rollout compute at scale (models up to 122B, 256K context).
- **Theme:** Core LLM (RL post-training / inference efficiency)
- **Relevance note:** Removes a real systems blocker for agentic RL on long-context coding trajectories — complements Miles v0.1 above.
- **Link:** https://arxiv.org/abs/2609.07108

## 7. ExecCritic: Learn to Test, Test to Improve for Coding Agents
- **Authors:** Leitian Tao, Baolin Peng, Haorui Wang, et al.
- **Summary:** ExecCritic splits a coding agent into a Test agent that authors repository-specific executable specifications and a separate Repair agent that consumes the resulting execution feedback, each trained with a role-specific RL objective. The Test agent's own success rate jumps from 22.2% to 62.2%, and the combined system reaches 72.6% on SWE-bench Verified (+11.4 pts) without stronger backbones or oracle tests at eval time.
- **Theme:** Spec-driven / verification-oriented development for coding agents
- **Relevance note:** Closest match to "specifications defining correctness of agent outputs for coding" in the window — tests are the executable spec, and the agent explicitly learns to write them.
- **Link:** https://arxiv.org/abs/2609.09133
