## 1. RISE: Recursive Improvement via Self-Extrapolating Policy Distillation
- **Authors:** Yang Li, Semih Yavuz, Shafiq Joty (Salesforce AI Research)
- **Summary:** RISE tackles the sparsity of trajectory-level RL rewards by turning the model's own RL rollouts into dense per-token supervision, then recursively distilling the extrapolated policy back into the base model so each round bootstraps the next. The reported result is that this recursive self-distillation loop improves post-training gains on reasoning benchmarks beyond what plain RLVR yields for the same rollout budget, without requiring a stronger teacher.
- **Theme:** Core LLM advances (fine-tuning / post-training)
- **Relevance:** Directly targets fine-tuning + reasoning under RL, a central bottleneck for training agentic reasoners at bearable compute cost.
- **Link:** https://arxiv.org/abs/2609.05295

## 2. Bilevel Coordinated Reflection: A Game-Theoretic Approach to Multi-Agent LLM Systems
- **Authors:** Yihang Chen, Yuxiang Chen, Yuxuan Huang, et al.
- **Summary:** The paper formalizes multi-agent LLM interaction as a bilevel game in which each agent's action policy sits under a meta-level reflection policy that updates a stochastic shared memory. The authors prove convergence conditions for the coordinated reflection dynamics and show empirically that it stabilizes multi-agent debate/critique loops that otherwise oscillate or collapse to a single voice.
- **Theme:** Multi-agent frameworks & orchestration
- **Relevance:** Rare theoretical grounding for orchestration protocols; matches the "coordination + shared memory" axis of the theme.
- **Link:** https://arxiv.org/abs/2609.02750

## 3. Iris: Climbing to the Search Frontier
- **Authors:** Ziyuan Liu, Hengqi Liu, Zichuan Wang, et al.
- **Summary:** Iris is a search-agent training recipe that alternates SFT and RL "climbing" rounds, with trajectory filtering to keep only successful search paths and an explicit context-management module to control token growth over long tool-use rollouts. The report claims SOTA on web-search agent benchmarks at practical rollout lengths, without domain-specialized retrievers.
- **Theme:** Core LLM advances (planning, agentic-system evaluation)
- **Relevance:** Concrete end-to-end recipe for training search agents; the trajectory-filtering and context-management ideas transfer to any tool-using agent stack.
- **Link:** https://arxiv.org/abs/2609.04304

## 4. MaxKernel: Agentic Kernel Generation for TPUs
- **Authors:** Shangkun Wang, Nina Cai, Charles Hoong, et al. (Google)
- **Summary:** MaxKernel is a multi-agent system that decomposes TPU kernel authoring into role-specialized agents (drafter, profiler, optimizer, verifier) running in both collaborative and fully autonomous modes over Pallas/XLA. On the reported kernels the pipeline reaches expert-level performance, replacing hand-tuned templates with an agent-generated equivalent.
- **Theme:** Multi-agent frameworks & orchestration (coding application)
- **Relevance:** Concrete role/tool-assignment case study for coding — directly on-target for spec-driven coding-agent work and shows the orchestration paying off in a hard, measurable domain.
- **Link:** https://arxiv.org/abs/2609.04523

## 5. τ^τ-Bench: An Environment for End-To-End, Realistic Agent Construction
- **Authors:** Quan Shi, Keshav Dhandhania, Karthik Narasimhan, Victor Barres (Sierra Technologies)
- **Summary:** τ^τ-Bench (tau-tau) is a benchmark whose tasks are themselves *building* a customer-service agent from real business records and production API specs, so coding agents are evaluated on end-to-end agent construction rather than isolated function synthesis. Each task ships a spec, an API surface, and a graded evaluator that scores the resulting agent's behavior against the specification.
- **Theme:** Multi-agent frameworks & orchestration (evaluation)
- **Relevance:** Fills a real gap: evaluation harnesses for agents that themselves build agents, and does so with grounded specs — bridges into the spec-driven-coding theme too.
- **Link:** https://arxiv.org/abs/2609.04611

## 6. Compile by Training: Turning Natural-Language Specifications into Local Neural Functions
- **Authors:** University of Waterloo (authors not fully listed on HF card)
- **Summary:** The paper proposes treating a natural-language spec as a compilation target: instead of prompting a general LLM at inference, it trains small "local neural functions" whose weights encode the spec, so callers get deterministic behavior per spec. The system evaluates whether spec conformance and compositionality improve versus prompt-time interpretation of the same spec.
- **Theme:** Spec-driven development & formal verification (coding)
- **Relevance:** Direct spec-as-source-of-truth angle for coding-adjacent agent behavior; interesting alternative to prompt-based interpretation of specs.
- **Link:** https://arxiv.org/abs/2609.04199

## 7. When Models Edit Too Much: On the Fidelity of Minimal Code Edits
- **Authors:** Tongyao Zhu, Wei Hern Lim, Min-Yen Kan (NUS)
- **Summary:** The authors quantify "over-editing" in code-repair models — cases where the fix is correct but the model rewrites far more of the file than the spec required — and show that adding explicit preservation instructions plus an RL reward for edit-locality substantially improves edit fidelity without regressing pass rates. Fidelity is treated as a spec-conformance property, not just correctness.
- **Theme:** Spec-driven development & formal verification (coding)
- **Relevance:** Concretely defines and optimizes a spec-style correctness criterion (minimal-diff) for coding agents; useful when wiring agent outputs into review or CI.
- **Link:** https://arxiv.org/abs/2609.04061

## 8. RealSWE: A Compositional Evaluation of Coding Agents under Realistic User Requests
- **Authors:** Sungkyunkwan University (authors not fully listed on HF card)
- **Summary:** RealSWE assembles multi-turn, compositional user requests (bug fix + refactor + docs update, etc.) drawn from real repositories and grades a coding agent on whether the *sequence* of edits still satisfies every earlier spec, not just the last one. The paper reports that current top coding agents regress on earlier spec items as later ones are addressed, exposing a spec-consistency failure mode.
- **Theme:** Spec-driven development & formal verification (coding-agent evaluation)
- **Relevance:** Fills a gap between SWE-bench-style single-goal evals and realistic multi-spec user sessions; useful yardstick for spec-driven agent work.
- **Link:** https://arxiv.org/abs/2608.27831

## 9. Beneath the Surface of Chains-of-Thought: A Mechanistic Interpretation of Reasoning Operations in LLMs
- **Authors:** Seogyeong Jeong, Jaehui Hwang, Dongyoon Han, et al. (NAVER AI Lab)
- **Summary:** The paper probes hidden states across chain-of-thought steps and shows that distinct reasoning operations (arithmetic, comparison, retrieval, deduction) occupy separable subspaces that align across problems and models. This gives a per-operation geometric fingerprint that can be used to detect when a model is executing a claimed reasoning step vs. surface-imitating one.
- **Theme:** Core LLM advances (reasoning interpretability)
- **Relevance:** Mechanistic handle on reasoning could feed directly into verification of agent outputs — knowing which "operation" a step actually was is useful for spec-grounded checks.
- **Link:** https://arxiv.org/abs/2609.04753

## 10. Locked at the Entrance, Open Inside: Where RLVR Narrows the Solution Space
- **Authors:** University of Birmingham (authors not fully listed on HF card)
- **Summary:** The paper dissects RLVR-trained reasoners and finds that the narrowing effect (mode collapse to a preferred solution) happens almost entirely at the first-token / first-step "entrance" while later steps retain diversity; interventions on the entry distribution recover exploration without harming pass-rate. This reframes what to regularize in RL post-training for reasoning.
- **Theme:** Core LLM advances (reasoning / RL post-training)
- **Relevance:** Diagnostic result that changes practical fine-tuning: the fix isn't broader per-step entropy, it's an entry-distribution intervention.
- **Link:** https://arxiv.org/abs/2608.29188
